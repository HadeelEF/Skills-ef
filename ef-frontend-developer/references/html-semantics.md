# هندسة HTML وبنية الواجهة

## Choose elements by meaning and behavior

ابدأ من محتوى الصفحة ورحلة المستخدم، ثم اختر عناصر HTML التي تمثلها.
عند استخدام React أو مكتبة مكونات، راجع DOM الناتج؛ اسم المكوّن لا يثبت
دلالته أو صحة تركيبه. اربط قرارات العرض بـ[التنفيذ البصري](visual-implementation.md).

| الحاجة | القرار العملي |
| --- | --- |
| الانتقال إلى وجهة | رابط ذو `href` حقيقي؛ حافظ على فتحه في تبويب جديد ونسخ عنوانه |
| تنفيذ فعل أو تغيير حالة | `button` مع نوع صريح؛ `type="button"` للفعل الذي لا يرسل النموذج |
| مجموعة متكررة | قائمة عند وجود علاقة قائمة؛ لا تجعل كل غلاف `section` أو landmark |
| بيانات ذات صفوف وأعمدة | جدول وعناوين مرتبطة بالخلايا؛ لا تستخدم جدولًا لتكوين الصفحة |
| فقرة وعنوان | رتبة عنوان بحسب تسلسل المحتوى؛ حجم الخط مستقل عن رتبة العنوان |
| مناطق الصفحة | مناطق دلالية مناسبة ومحتوى رئيسي واضح؛ ميّز أسماء مناطق التنقل المتعددة |

لا تضع زرًا داخل رابط أو زر آخر، أو نموذجًا داخل نموذج. لا تعالج تداخلًا
غير صالح بإيقاف انتشار الأحداث فقط. في بطاقة ذات أفعال متعددة، افصل رابط
العنوان عن الأزرار واحفظ ترتيب التنقل. قد يصحح محلل HTML التداخل غير الصالح
إلى DOM مختلف؛ افحصه عند مشكلات SSR وhydration قبل إخفاء التحذير.
مرجع: [WHATWG content models](https://html.spec.whatwg.org/multipage/dom.html#content-models).

## Make forms work as forms

- استخدم `form` ومسار إرسال موحدًا حيث توجد عملية إرسال؛ افحص Enter
  وزر الإرسال، وتجنب تنفيذ العملية مرتين عبر معالجي click وsubmit.
  مرجع النوع والسلوك: [HTML button](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button).
- اربط `label` بالحقل بمعرّف فريد، ومجموعة الاختيارات بـ`fieldset/legend`
  حين يناسبها. في React استخدم معرّفات مستقرة مناسبة مثل `useId` لربط
  المكونات المتكررة؛ لا تستخدمها بديلًا لمفاتيح بيانات القوائم.
- اختر `type` و`inputmode` و`autocomplete` حسب معنى البيانات. رقم الجوال
  ورقم الطلب ليسا بالضرورة عددًا حسابيًا؛ احتفظ بالأصفار والرموز. تلميح
  لوحة المفاتيح لا يحقق صحة البيانات، و`placeholder` لا يغني عن التسمية.
- إذا اعتمد الإرسال على `FormData` أو الإرسال الأصلي، تحقق من `name`
  والقيم المرسلة، وخاصة مربعات الاختيار والحقول المعطلة. `disabled`
  يستبعد الحقل من الإرسال الأصلي ومن التركيز؛ `readonly` للأنواع التي تدعمه
  يسمح بالتركيز والإرسال. اختر وفق الحاجة إلى القراءة والنسخ والمراجعة.
  [Disabled controls](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled).
- اجعل استراتيجية التحقق متسقة: native validation أو رسائل مخصصة مكتملة.
  لا تستخدم `novalidate` لمجرد إسكات مشكلة. إذا كان نص الأخطاء مطلوبًا
  بلغة واجهة محددة فلا تفترض أن رسائل المتصفح تتبعها تلقائيًا.

تفاصيل الأخطاء والحفظ وصلاحية البيانات عند الخادم في
[النماذج والبيانات](forms-and-data.md)، وإدارة التركيز والإعلان عن الأخطاء في
[الإتاحة واللغتين](bilingual-accessibility.md). لا تستنتج صلاحية المستخدم
من وجود حقل مخفي أو زر معطل.

## Preserve structure through composition

افحص `as` و`asChild` والعناصر التي ترسمها مكونات التصميم عند تركيبها.
لا تجعل abstraction عامًا يسمح بمزيج عنصر ودور وسلوك غير متوافق. مرر
المعرّفات والأسماء الميسرة والخصائص الأصلية ذات الصلة دون إسقاطها.

اختَر السلوك الأصلي حين يلائم التفاعل، مثل `details/summary` للكشف البسيط.
في الحوار، يختلف فتح `dialog` عبر `showModal()` عن إظهار عنصر بوضع `open`
أو CSS فقط: الأول يوفر السلوك المشروط والطبقة العليا. افحص الاسم والتركيز
والإغلاق وإعادته إلى الموضع المناسب في التطبيق الفعلي. لا تفترض أن أي
popover هو modal أو أن إضافة دور ARIA تنفذ سلوكه.
[HTML dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

في الجداول، اربط العناوين بالصفوف أو الأعمدة حسب التعقيد. إذا تحولت إلى
بطاقات في الجوال فاحتفظ باسم كل قيمة وعلاقتها؛ راجع DOM وشجرة الإتاحة
إذا غيّرت خصائص العرض. لا تجعل الصف القابل للنقر البديل الوحيد لرابط أو زر.

## Integrate images and document metadata

حدّد وظيفة الصورة قبل `alt`: معلومة، فعل، أو زخرفة. إن احتوى الرابط على
صورة ونص كافٍ، تجنب تكرار اسمه دون حاجة. لا تخفِ معلومة مهمة داخل خلفية CSS
أو `::before`. استخدم أصول الصندوق من المرجع المشترك واحفظ نسبها.

عند تعدد ملفات الصورة، اجعل `srcset/sizes` يعكسان حجم العرض المتوقع؛
`sizes` يساعد الاختيار ولا يحدد عرض CSS. استخدم `picture` لتغيير الاقتصاص
أو تقديم بدائل مناسبة عند الحاجة، مع `img` بديل. احجز مساحة بنسبة صحيحة
لتقليل تغير التخطيط، ولا تؤخر الصورة الأساسية المرئية تلقائيًا.
[Responsive images](https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Responsive_images).

اضبط عنوان الصفحة و`lang/dir` وبيانات viewport في موضعها الصحيح وفق الإطار.
لا تمنع تكبير المستخدم. طبّق metadata الخاصة بالمشاركة والفهرسة عندما
تخص صفحة عامة؛ لا تعامل بوابة داخلية كصفحة تسويقية. تفاصيل SEO والعرض في
[الأداء والتسليم](performance-and-delivery.md).

## Diagnose the rendered document

عند تعطل عنصر، افحص العنصر الناتج واسمه ودوره وحالته وارتباطه بالنموذج
والحدث الافتراضي قبل إضافة JavaScript تعويضي. عند اختلاف الخادم والعميل،
قارن HTML المستلم وDOM المحلل والعرض الأول وفق
[العرض والتوجيه](rendering-and-routing.md).

استخدم فحص صلاحية HTML أو شجرة الإتاحة عندما توجد شبهة تركيب أو دلالة،
مع اختبار السلوك الفعلي. اجعل الروابط والإرسال يعملان دون JavaScript حيث
يدعم نطاق المنتج وإطاره ذلك؛ إذا كان التطبيق يعتمد عليه فصرّح بالاعتماد
ولا تعِد بتحسين تدريجي لم تنفذه.
