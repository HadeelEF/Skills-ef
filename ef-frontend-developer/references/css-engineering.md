# هندسة CSS وتنفيذ التخطيطات

## Own the visual system

حوّل مواصفات التصميم إلى علاقات واضحة: عرض المحتوى، تقسيم المساحات،
المحاذاة، كثافة النص، حالات التفاعل والتحول مع تغير المساحة. التفاصيل
الدقيقة تأتي من التصميم و[مرجع التنفيذ البصري](visual-implementation.md).
لا تثبت الصفحة بإحداثيات مطلقة كي تطابق لقطة واحدة.

احترم أسلوب المشروع: CSS مباشر أو CSS Modules أو Tailwind أو النظام القائم.
CSS Modules يعزل أسماء classes، لكنه لا يلغي الوراثة والتدفق وcascade.
في Tailwind افحص CSS الناتج وترتيب قواعده؛ ترتيب الأسماء في `className`
لا يمثل قاعدة عامة للأولوية. لا تضف نظام تنسيق آخر قبل إثبات حاجة.

## Control the cascade deliberately

افصل قيم التصميم المشتركة عن قواعد المكوّن وحالاته؛ استخدم custom properties
لـtokens والأوضاع حين تفيد. اجعل selectors محلية وبخصوصية مناسبة بدل ربط
كل قاعدة بسلسلة DOM طويلة. استخدم طبقات `@layer` إذا كان ترتيب reset
والمكتبة والمكونات يحتاج عقدًا واضحًا.

عند تعارض قاعدة افحص origin وimportance والطبقة وspecificity وترتيب
التعريف، لا عدد selectors وحده. القواعد العادية خارج الطبقات تتقدم على
القواعد العادية داخلها؛ ترتيب الطبقات مع `!important` معكوس. لذلك نقل
مكتبة إلى طبقة أو إضافة `!important` قد يغير النتيجة على نطاق واسع.
افحص القاعدة الفائزة والخصائص الموروثة والمتغيرات في DevTools قبل التعديل.
[MDN cascade](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Introduction).

## Build intrinsically resilient layouts

| التكوين | قرار التخطيط |
| --- | --- |
| صف أفعال أو تنقل مرن | Flex مع قرار واضح للالتفاف والتمدد والانكماش |
| صفوف وأعمدة تحتاج محاذاة مشتركة | Grid مع مسارات وأحجام دنيا تناسب المحتوى |
| محاذاة أجزاء مكونات متداخلة مع الشبكة الأم | قيّم `subgrid` في المحور المطلوب مع توافق المتصفحات |
| مكوّن يظهر في عمود جانبي وفي مساحة واسعة | قيّم container query بحسب مساحة حاضنه |
| شارة فوق صورة أو زخرفة مستقلة | تموضع مقصود مع containing block معروف ومساحة محفوظة للمحتوى |

عند overflow، افحص box model و`box-sizing` و`gap` والحجم الجوهري للنص
والصورة. قد يمنع الحد الأدنى التلقائي عنصر Flex/Grid من الانكماش؛ استخدم
`min-inline-size:0` حيث يسمح التصميم بذلك، أو `minmax(0,1fr)` للمسار المرن
المناسب. ثم قرر هل يلتف المحتوى أم يمرر أم يختصر. هذه القيم لا تصلح النص
الطويل وحدها، ولا تبرر قص المعلومات أو إخفاء التمرير عن كامل الصفحة.
[Automatic minimum sizing](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width).

استخدم `subgrid` حين تحتاج مشاركة خطوط الشبكة الأم فعلًا؛ اختر المحور
والمسارات التي يمتد عليها المكوّن. لا تفترض أن كل شبكة متداخلة subgrid،
ولا تفرضه على مكوّن يجب أن يبقى مستقلًا.
[Subgrid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid).

## Choose responsive rules by available space

ابدأ من المحتوى الحقيقي وأصغر مساحة مطلوبة، ثم غيّر التكوين عند انهيار
المحاذاة أو القراءة. استخدم media queries لتكوين الصفحة، وsize container
queries لتكيف مكوّن مع حاضنه. عرّف حاضنًا مناسبًا مثل `container-type:inline-size`؛
الاستعلام يختار حاضنًا مؤهلًا من الأسلاف، ولا يقيس العنصر نفسه لتغيير حجمه
بالقاعدة ذاتها. راعِ أثر containment على sizing، وسمّ الحاضن عند التداخل
إذا كان اختيار الأقرب غير مناسب.
[Container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries).

اختر بين `svh` للمساحة الصغيرة المستقرة و`dvh` للمساحة الديناميكية وفق
سلوك الشاشة، مع fallback حسب المتصفحات المستهدفة. تجنب ارتفاع ثابت
لشاشة تحتاج نمو المحتوى؛ اختبر شريط المتصفح ولوحة المفاتيح عند وجود حوار
أو أفعال ثابتة أسفل الجوال. وحدات viewport وحدها لا تثبت دعم كل سلوك
للوحة المفاتيح. أضف safe-area insets حين يمتد التصميم إلى حواف الجهاز.
[Viewport lengths](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length).

قواعد RTL والخصائص المنطقية وترتيب القراءة في
[الإتاحة واللغتين](bilingual-accessibility.md). تحقق أن media/container
queries تستوعب اختلاف طول الترجمة، وأن إخفاء نسخة من التنقل لا يترك عناصر
غير مرئية قابلة للتركيز.

## Set typography and states with intent

طبّق الخط والأوزان الفعلية من مرجع الهوية، وراجع تحميلها وفق
[التنفيذ البصري](visual-implementation.md). اضبط ارتفاع السطر ومقاس النص
وعرض العمود حسب العربية والإنجليزية؛ لا تنقل letter-spacing المستخدم
للحروف اللاتينية إلى النص العربي تلقائيًا.

يمكن استخدام `clamp()` للقياسات المرنة بحدود مفهومة؛ في النص اجعل الوحدات
والحدود تحترم إعدادات الخط والتكبير، وافحص النتيجة بدل افتراض أن كل قياس
مرن ميسر. لا تضع ارتفاعًا ثابتًا يحذف سطرًا أو تشكيلًا. اختصار النص قرار
محتوى يحتاج وسيلة للوصول إلى المعلومة الكاملة عندما تكون لازمة للمهمة.

غطِّ الحالات اللازمة: hover وfocus-visible وactive وdisabled وinvalid
والانشغال والاختيار. طابق CSS مع حالة العنصر الفعلية؛ `aria-disabled`
أو `pointer-events:none` وحدهما لا ينفذان تعطيلًا كاملًا بلوحة المفاتيح.
لا تجعل اكتشاف الأفعال معتمدًا على hover في اللمس. احفظ وضوح التركيز في
الألوان المفروضة والتباين المطلوب عند انطباقها.

في الحركة، اربط الانتقال بتغير مفهوم في الحالة واحترم `prefers-reduced-motion`.
تجنب `transition:all` عندما يسبب تحريك التخطيط أو حالات غير مقصودة. قيّم
transform/opacity للحركة المناسبة، ولا تضف `will-change` دائمًا لكل مكوّن.
التقييم الفعلي للأداء في [الأداء والتسليم](performance-and-delivery.md).

## Diagnose position and overlap

| العَرَض | ما يُفحص قبل الحل |
| --- | --- |
| القائمة تختفي خلف جزء آخر | stacking contexts للأسلاف، موضع portal، وقيود القص |
| `z-index` كبير بلا أثر | سياق العنصر بالنسبة إلى السياق المنافس؛ الرقم لا يخرج الابن من سياق أبيه |
| sticky لا يثبت أو يثبت في موضع غريب | scroll ancestor، overflow، inset غير auto، والمساحة المتاحة للحركة |
| fixed يتحرك مع حاوية | containing block الذي قد ينشئه transform أو خاصية أخرى في الأسلاف |
| حقل أو عنوان محجوب خلف ترويسة | scroll padding/margin المناسب، ارتفاع الترويسة الحقيقي وسلوك التركيز |

افحص stacking context الذي قد تنشئه خصائص مثل transform أو opacity قبل
زيادة الرقم. الطبقة العليا للحوارات ليست مجرد قيمة أعلى داخل سلم z-index.
[Stacking context](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context).
وعند sticky/absolute/fixed افحص scroll container وcontaining block كلًا
بحسب وظيفته؛ تغيير overflow قد يؤثر في الاثنين وفي قص التركيز.
[Position](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position).

## Verify the actual failure and correction

عند اختلاف مرئي، أعد إنتاج نفس اللغة والمقاس والحالة، ثم افحص DOM وcomputed
styles وbox metrics والخط المستخدم وGrid/Flex overlays. صغ سببًا قابلًا
للتحقق، أصلحه عند مصدره، وأعد فحص الموضع والمواضع التي تشارك القاعدة.
قياس padding وحده لا يثبت المسافة المرئية إذا تدخلت المحاذاة أو فراغات الأصل.

اختر من الحالات ما يهدد التغيير: نص طويل، حاضن أضيق مع viewport ثابت،
تكبير، الاتجاه الآخر، حوار مفتوح، أو حدود breakpoint. شاهد الصفحة فعليًا؛
قياس `scrollWidth` وحده لا يكشف قصًا مخفيًا أو تداخلًا أو فقد محتوى.

تحقق من دعم الخاصية في المتصفحات المطلوبة عند استخدام ميزة متغيرة.
استخدم `@supports` وfallback مفيدًا عند الحاجة؛ دعم صياغة خاصية لا يضمن
خلو سلوكها من العيوب. لا تدعِ دعم Safari أو Firefox من تجربة Chromium.
إذا شملت المهمة الطباعة، افحص معاينتها وتجزئة المحتوى وإخفاء الأفعال غير
اللازمة؛ الطباعة من الويب ليست بديلًا تلقائيًا لملف Word مطلوب.
