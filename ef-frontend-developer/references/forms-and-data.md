# النماذج والبيانات والتكامل

## Work from a contract

افهم API أو نموذج البيانات المتاح قبل ربط الشاشة: الحقول ومعانيها وأنواعها،
القيم الغائبة، الحالات، الفرز والترقيم، صيغ الأخطاء، ومتطلبات الهوية والصلاحية.
لا تحول أسماء حالات العرض أو رسالة وهمية إلى عقد خادم معتمد.

عند عدم توفر API، استخدم adapter أو fixtures بسيطة معلنة عندما يحتاج
النطاق إلى نموذج تفاعلي، وحدد شكل التكامل المقترح في تسليم المشروع. أبقِ
المحاكاة قابلة للاستبدال، وسمِّ نقاط الربط غير المنفذة؛ لا تنشئ backend
أو مزود مصادقة أو قاعدة بيانات لمجرد إكمال واجهة ما لم يدخل ذلك في الطلب.

## Fetch and render honestly

فرّق بحسب الشاشة بين التحميل الأول، تحديث بيانات معروضة، نجاح بنتائج،
فراغ، فشل، وحالات عدم الصلاحية أو انتهاء الجلسة. لا تضف كل حالة شكليًا
إن لم تكن ممكنة؛ ولا تعرض رسالة «لا توجد نتائج» أثناء جلب لم يكتمل.

- افحص HTTP status وعقد الاستجابة؛ `fetch` لا يرفض الوعد لمجرد استجابة 4xx
  أو 5xx. تعامل مع الاستجابة غير المتوقعة دون تحويلها إلى نجاح بصمت.
- تحقق من البيانات عند الحدود بما يناسب التكامل. TypeScript وحده لا يثبت
  صحة JSON؛ Zod أو تحقق مكافئ مفيد عند الحاجة، دون تكرار schema متنافس.
- امنع استجابة بحث قديم من استبدال نتيجة أحدث، بإلغاء الطلب أو تجاهل نتيجة
  تجاوزها الطلب الجديد وفق المكتبة. احتفظ بالمرشحات عند إعادة المحاولة.
- اجعل query key يشمل ما يغير النتيجة: المرشحات والترقيم ونطاق المستخدم
  واللغة إذا كانت الاستجابة مترجمة. لا تضف اللغة إلى المفتاح إذا كانت
  البيانات مستقلة عنها بلا حاجة.
- افصل بيانات المستخدمين أو المؤسسات، وامسح أو غيّر نطاق cache عند الخروج
  أو تغير الهوية. إخفاء مكوّن لا يمنع ظهور بيانات قديمة من ذاكرة التطبيق.
- استخدم سياسة retry مناسبة؛ طلب قراءة مؤقت الفشل يختلف عن عملية إنشاء
  قد تتكرر. بعد تعديل ناجح حدّث أو أبطل الاستعلامات المتأثرة فعليًا.

أزرار الفرز والبحث والترقيم تغير النتيجة الحقيقية، لا المظهر وحده. إذا كان
الفرز في العميل فوق صفحة واحدة فقط، فلا تقدمه كفرز لكامل بيانات الخادم.
حدد أثر تغير المرشح على الصفحة الحالية، وافحص رجوع المتصفح إذا حفظت الحالة
في URL. استعمل debounce فقط عندما يخدم زمن الاستجابة وطريقة البحث.

مراجع: [Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)،
[TanStack Query keys](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys)،
[Zod basics](https://zod.dev/basics).

## Forms that preserve the user's work

ابنِ على controls أصلية أو مكونات ميسرة. لكل حقل label ونوع إدخال وتلميح
أو وحدة عند الحاجة. افصل القيمة المعروضة عن القيمة المرسلة عندما يختلف
التنسيق، مثل المبالغ والتواريخ.

استخدم React Hook Form وschema عند فائدتهما، مع رسائل عربية وإنجليزية
ومصدر واضح للقواعد. لا تحول كل قيمة رقمية خالية إلى صفر، أو تحقق بريد
بصيغة تمنع عناوين صحيحة. لا تخترع متطلبات أهلية أو طول حقل أو حد ملف رسميًا.
مرجع: [React Hook Form](https://www.react-hook-form.com/).

اعرض الخطأ في موضع يساعد على الإصلاح، واربطه بالحقل ميسرًا. انقل التركيز
إلى موضع مفيد بعد محاولة إرسال غير صالحة وفق حجم النموذج. احتفظ بالمدخلات
عند فشل الشبكة أو الخادم، ولا تمسح النموذج إلا بعد نجاح مؤكد أو قرار واضح.

تحقق العميل يحسن الاستخدام؛ يظل الخادم مسؤولًا عن قبول البيانات والتحقق
من الصلاحية. اعرض أخطاء الخادم المعروفة بصياغة مفيدة دون تسريب تفاصيل داخلية.

## Mutation outcomes

حدد للكتابة أو الإرسال: متى يبدأ الانشغال، كيف يُمنع التكرار، ماذا يؤكد
النجاح، ماذا يحدث للفشل المؤكد، وكيف تعالج نتيجة لم يُعرف مصيرها.

انقطاع الاتصال أو مهلة الانتظار بعد إرسال طلب قد يعني أن الخادم نفذ
العملية لكن الرد لم يصل. لا تؤكد «لم يُحفظ» دون دليل، ولا تعاود إرسال
عملية غير آمنة تلقائيًا. استخدم idempotency أو الاستعلام عن الحالة إذا
دعمه العقد، وإلا اعرض صياغة محايدة وخطوة تحقق مناسبة مع بقاء المدخلات.

التحديث المتفائل مناسب عندما تكون النتيجة قابلة للتراجع ومعروفة؛ حدّد
rollback والتزامن والفشل. لا تستخدمه لإظهار اعتماد رسمي أو نجاح دفع أو
حفظ نهائي قبل أن يؤكده النظام. وعود السلوك تتبع قدرات API الفعلية.

## Authorization and sensitive data

إخفاء زر غير مسموح مفيد للواجهة لكنه ليس فرضًا للصلاحيات. لا تدّعِ حماية
عملية ما لم يتحقق الخادم منها. نفذ التعامل مع الجلسة وفق نظام المشروع؛
لا تنقل tokens إلى تخزين دائم أو تضف مزودًا جديدًا بلا حاجة.

لا تضع الأسرار في كود العميل أو متغيراته العامة أو السجلات واللقطات.
اعرض المحتوى غير الموثوق كنص؛ إن احتاج المنتج HTML غنيًا، استخدم تعقيمًا
مناسبًا لنطاقه ولا تجعل `dangerouslySetInnerHTML` اختصارًا لعرض بيانات API.

في رفع الملفات، طبّق نوعًا وحجمًا مثبتين من العقد، مع تقدم وإلغاء وخطأ
حيث تدعم الآلية. لا تصف فحص المتصفح كحماية خادم أو معالجة ملف ناجحة.
اختبر التكامل ببيانات وبيئة مناسبة؛ إرسال نموذج اختبار إلى خدمة حقيقية
ليس إجراءً محليًا لمجرد أن زرّه في واجهة قيد التطوير.
