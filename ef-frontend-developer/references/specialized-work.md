# Figma والاحتياجات المتخصصة

هذه قدرات تُستخدم عندما تدخل في الطلب. لا تثبّت أدواتها أو توسّع نطاق
المشروع لمجرد وجود هذا المرجع.

## Figma as a design source

عندما يقدّم المستخدم رابطًا أو يطلب التنفيذ من Figma، استخدم الأدوات
المتصلة المتاحة ومهاراتها اللازمة. إذا كانت البيئة تتطلب مهارة قبل أداة
قراءة التصميم، اقرأها أولًا. لا تفترض أسماء أدوات أو صلاحيات ثابتة عبر
Codex وClaude Code وChatGPT وغيرها.

اقرأ frame/node المقصود ونسخته وسياقه ولقطته عند توفرها؛ استخرج layout
وvariables/styles والمكونات وحالاتها والنصوص والأصول. اربطها بنظام المشروع
ومرجع EF. حافظ على مكونات الكود الحالية عندما تحقق التصميم، ولا تثق في
كود مولد باعتباره جاهزًا دون فحص السلوك واللغتين والإتاحة.

إذا افتقر تصميم Figma إلى حالة أو لغة، حل الفجوة من مواصفات المشروع أو
بقرار محدود واضح، واستعن بمهارة UI/UX عند الحاجة. لا تدّعِ مطابقة شاشة
لم تتوفر لك بياناتها أو لم ترها. عند غياب الاتصال استخدم التصدير أو الصور
والمواصفات المتاحة وحدد ما لم يمكن التحقق منه.

القراءة والتنفيذ من Figma لا يعنيان تلقائيًا طلب إنشاء ملف أو تعديل مكتبة
مشتركة فيه. عندما يطلب المستخدم تلك المخرجات، اتبع مسار الإنشاء/التعديل
المتاح، وسلّم الرابط أو node الفعلي. Markdown أو صورة ثابتة لا يثبتان أن
ملف Figma أُنشئ.

## Tables, dashboards and charts

ابدأ بالسؤال الذي يريد المستخدم الإجابة عنه والبيانات المتاحة. اختر النوع
والمحاور والوحدات والدقة الزمنية وفق ذلك. لا تملأ dashboard بمؤشرات مختلقة
لتبدو مكتملة؛ سمِّ أمثلة البيانات بوضوح.

راعِ الأعداد الكبيرة والفراغ والقيم الناقصة واختلاف المقارنة عن الإجمالي.
أضف شرحًا أو جدول بيانات بديلًا عندما تحتاج دلالة الرسم إليه. اللون وحده
لا يكفي لتمييز السلاسل؛ اختبر التباين والتسميات وRTL والتلميحات والتنقل
بالكيبورد وفق المكتبة المختارة. لا تعكس المحور الزمني آليًا لمجرد تغيير اللغة.

في الجداول المركبة، حافظ على العلاقة بين العناوين والخلايا، وأوضح نطاق
الاختيار والفرز والترقيم والتحميل. Excel أو CSV export يجب أن يصدر البيانات
المقصودة فعلًا، مع معالجة المحتوى غير الموثوق إذا كان سيفتح في جدول بيانات.

## Motion

استخدم الحركة لتوضيح تغير الحالة أو العلاقة المكانية، وفق التصميم. حدد
مدتها وسببها، واحترم `prefers-reduced-motion`، وتجنب حجب التفاعل أو ربط
إتمام المهمة بانتهاء أنيميشن طويل. CSS يكفي للحالات البسيطة؛ أضف مكتبة
عندما يبررها التفاعل المركب أو النظام القائم. افحص الحركة على جهاز/مقاس
مناسب لا لقطة ساكنة فقط.

## Mobile scope

واجهة ويب متجاوبة تعمل على الجوال ضمن النطاق الأساسي. React Native/Expo
أو تطبيق native نطاق مختلف: حدده من طلب المستخدم قبل اختيار التقنية.
لا تصف نسخة ويب بأنها تطبيق متجر أو توهم أن مكونات DOM وCSS تنتقل كما هي.

عند طلب native صراحة، افحص المشروع وأدوات البناء والمنصات المستهدفة؛ استخدم
المراجع الرسمية ومهارة متخصصة متاحة. اختبر قيود RTL والخطوط والإدخال الآمن
والتنقل وسلوك المنصة في بيئة فعلية مناسبة. إذا لم تتوفر، بيّن بدقة ما بُني
وما لم يُشغّل على المنصة. مرجع البداية: [Expo](https://docs.expo.dev/).

## Additional services

CMS أو خرائط أو مصادقة أو واجهات ذكاء اصطناعي تدخل حسب المنتج. استخدم
التكامل القائم أو اختره بتبرير متناسب؛ لا تنشئ حسابات أو اشتراكات أو ترسل
رسائل أو ترفع بيانات لمجرد اختبار واجهة. يحتاج streaming إلى حالات انتهاء
وفشل وإلغاء، ومخرجات غير موثوقة إلى عرض آمن؛ أضف تلك المعالجة فقط عندما
تكون الميزة موجودة في الطلب.
