# الأداء والتشغيل والتسليم

## Improve measured bottlenecks

اختر معالجة تتفق مع حجم الصفحة وطريقة استخدامها. راقب الأجزاء الثقيلة:
حزم العميل، الصور، أوزان الخطوط، زمن البيانات، القوائم الكبيرة وتغير التخطيط.
لا تضف مكتبة أداء أو تهيئة معقدة دون تكلفة قابلة للتفسير.

- حدد أبعاد الصور أو نسبها لتجنب قفز المحتوى، واستخدم صيغة وحجمًا مناسبين
  وبدائل responsive عند الحاجة. لا تؤخر تحميل الصورة الرئيسية تلقائيًا.
- حمّل أوزان الخط المستخدمة فقط. استخدم caching وpreload بقدر الحاجة؛
  تحميل كل الأصول مسبقًا قد ينافس المحتوى المهم.
- افصل الحزم الثقيلة مثل محرر أو خريطة عندما لا تحتاجها البداية. لا تقسّم
  كل مكوّن صغير إذا كانت التكلفة والتعقيد أكبر من الفائدة.
- استخدم pagination أو virtualization عندما تتطلب البيانات ذلك مع الحفاظ
  على الإتاحة ووظائف البحث. لا تخف محدودية فرز صفحة واحدة وراء أداء أسرع.
- استعمل سياسة cache واضحة للبيانات وفق حساسيتها وحداثتها، وافحص تحديثها
  بعد التعديل. راجع حدود الخادم والعميل في مرجع المعمارية.

استخدم Core Web Vitals أو أدوات الإطار عند الحاجة، مع ذكر ما إذا كانت
القياسات مختبرية أو من مستخدمين فعليين. قارن في بيئة مناسبة ومتشابهة؛
لا تختلق نسبة تحسن أو score لم ينتج عن قياس.

## Profile React with a concrete question

اربط القياس بمهمة مثل الكتابة في بحث أو فتح تفاصيل أو تحديث قائمة.
اجمع baseline مناسبًا ثم حدد هل الزمن في الشبكة أو الحساب أو React render
أو layout/paint. استخدم React DevTools/Profiler وPerformance/Network أو
أدلة مكافئة متاحة؛ عدد render وحده لا يبين تكلفة تجربة المستخدم.

افحص أثر نقل state إلى موضعها، وتقسيم context/الاشتراكات، وثبات props
حيث يفيد memo، وتقليل حجم DOM، واستيراد الحزم الثقيلة. لا تضع `useMemo`
حول كل حساب أو تفترض أن `useCallback` يحسن كل مكوّن.

Transitions يمكن أن تجعل عرض React أقل إلحاحًا، لكنها لا تحول عمل JavaScript
متزامنًا ثقيلًا إلى خيط آخر. إذا ثبت أن الحساب يحجب التفاعل، قيّم تحسين
الخوارزمية أو تقسيم العمل أو Worker حسب البيانات والتكلفة. افحص أثره
على الإلغاء وعمر المكوّن ونقل البيانات قبل اعتماده.

قارن قبل/بعد في نفس المهمة والبيئة والبيانات. لا تخلط تكلفة Strict Mode
في التطوير مع إنتاج عادي. Profiler يضيف تكلفة ويحتاج بناء profiling خاصًا
لبعض قياسات الإنتاج؛ اذكر طريقة القياس وحدودها. أدوات الحزمة تبين وزن
الوحدات، وقياسات المستخدم تبين الأثر؛ لا تستنتج أحدهما من الآخر بلا دليل.
مرجع: [React Profiler](https://react.dev/reference/react/Profiler).

## Public pages and search

SEO مرتبط بالصفحات العامة التي ينبغي فهرستها. طبّق عنوانًا ووصفًا مناسبين
ولغة صحيحة وبنية عناوين وروابط حقيقية، ثم canonical وhreflang وخريطة الموقع
حيث تنطبق على بنية المشروع. لا تضع بيانات منظمة تصف جهة أو خدمة أو مراجعات
غير مثبتة.

لوحة داخلية محمية تحتاج إدارة وصول وسلوكًا صحيحًا قبل أي تحسين فهرسة.
`robots.txt` و`noindex` ليسا وسيلة حماية بيانات. الروابط المترجمة يجب أن
تصل إلى المقابل الفعلي لا الصفحة الرئيسية دائمًا.

## Build and environment

تحقق من أوامر التشغيل والبناء في المشروع. احتفظ بملف القفل وتوافق إصدار
بيئة التشغيل عندما تعتمد عليه النتيجة. متغيرات عامة مثل `NEXT_PUBLIC_*`
و`VITE_*` قد تصبح جزءًا من العميل؛ لا تضع فيها مفاتيح خاصة.

استخدم ملف أمثلة بيئة إذا احتاج التسليم إلى قيم يجب على المستلم توفيرها،
مع أسماء ووصف وقيم غير حساسة. لا تنسخ ملف أسرار فعليًا إلى ZIP أو تقرير
أو مستودع. بيّن إن كانت متغيرات البيئة تُقرأ وقت البناء أو التشغيل عندما
يؤثر ذلك في تغيير الإعدادات المنشورة.

اختبر مسارات الأصول، base path، والروابط العميقة وبناء الإنتاج عندما تمسها
المهمة. واجهة تعمل عبر proxy محلي قد تحتاج إعدادًا مختلفًا في الاستضافة؛
وضّح الاعتماد بدل تقديم معاينة محلية كخدمة منشورة.

## Leave a maintainable result

راجع diff واحفظ تعديلات المستخدم. لا تُدخل ملفات مؤقتة أو screenshots أو
اعتمادات تجريبية في المنتج بلا سبب. اتبع سياسة المستودع في مخرجات البناء
والصور الاختبارية. لا تغير إعدادات عامة على جهاز المستخدم لإصلاح مشروع محلي.

لا يلزم مستند جديد لكل تعديل. في تسليم مشروع كامل أو ميزة مركبة، حدّث
وثائقه القائمة بما يكفي ليكمل مطور آخر العمل:

| المعلومة | ما يحتاجه المستلم |
| --- | --- |
| نقطة البدء | المسار، أوامر التثبيت والتشغيل والبناء المجرّبة |
| التقنية | الإطار والإصدارات التي يعتمد عليها التشغيل والمدير/ملف القفل |
| التصميم | المواصفات المرجعية، قواعد الهوية المختارة، والتخصيصات المؤثرة |
| الأصول | الملفات المستخدمة ومصدرها ووجهتها وأوزان الخطوط |
| الوظائف | المسارات واللغات وما هو حقيقي أو توضيحي أو غير موصول |
| الإعداد | متغيرات البيئة المطلوبة والاعتمادات الخارجية دون أسرار |
| التحقق | ما نجح وما لم يفحص والقيود ذات الأثر |

التقرير النهائي يشرح النتيجة وكيف يجربها المستخدم. لا تسمِّ نموذجًا محليًا
متصلًا بـfixtures خدمة مكتملة من طرف إلى طرف. النشر يتطلب طلبًا أو تفويضًا
يشمله؛ عند دخوله في النطاق افحص إعداد الوجهة والتشغيل هناك ثم قدّم الرابط
الحقيقي. اتبع المهارة المتخصصة بالاستضافة إن كانت متاحة وملائمة.
