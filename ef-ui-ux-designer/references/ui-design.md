## Visual direction

صمم واجهة تخدم طبيعة العمل وتظهر هوية الصندوق. حدد نبرة التكوين وكثافته
ومواضع التركيز وفق الجمهور والمهمة: واجهة قراءة وتعريف، أو اكتشاف خدمة،
أو عمل متكرر كثيف البيانات. ترجم هذا إلى قرارات قابلة للتنفيذ عن المساحات
والتسلسل والمكونات، مع سبب موجز للقرارات المؤثرة.

استخرج الهوية من مرجع `ef-brand-guidelines` وفق عقد الاستهلاك في
[SKILL.md](../SKILL.md#use-the-shared-brand-authority). لا يحتاج تأسيس اتجاه
جديد إلى عينات سابقة. عند وجود منتج، ادرس مكوناته قبل تغيير أسسه.

اختر بنية الصفحة بحسب علاقتها بالمحتوى: أعمدة أو قائمة أو جدول أو تسلسل
تحريري أو بطاقات عندما تكون وحدات مستقلة فعلًا. وضوح الإجراء الرئيسي
وتوزيع الأهمية يوجهان عدد الحاويات والزخارف والتباين. حافظ على اتساق
المحاذاة والإيقاع وتوزيع المساحات بين اللغتين دون فرض تطابق بكسلي للنصوص.

## Foundations

أنشئ أسس المنتج المطلوبة أو استخدم الموجودة. لكل قيمة مشتركة: اسم ثابت،
قيمة أو قاعدة حساب، وحدة، دور، ومصدر القرار. هذه رموز تصميم للمشروع؛
وجودها لا يجعلها نظام تصميم رسميًا صادرًا عن الصندوق.

| الأساس | ما تحسمه |
| --- | --- |
| الألوان | قيم الهوية المختارة ثم أدوار السطح والنص والإجراء والحدود والتركيز والحالات؛ افحص الأزواج الفعلية |
| الخطوط | ملف العائلة والوجه والوزن الحقيقي، ثم مقاس وتباعد أسطر لكل دور بالعربية والإنجليزية |
| المسافات | سلم صغير متسق مرتبط بالكثافة، والفواصل الداخلية وبين الأقسام |
| التخطيط | عرض المحتوى وحدوده، الأعمدة والمحاذاة والممرات وسلوك الامتداد |
| الأشكال | الحدود وأنصاف الأقطار والارتفاعات والظلال حيث تخدم التجميع أو التفاعل |
| الحركة | الغرض والمحفز والمدة والسلوك البديل عند تقليل الحركة، إذا احتاجها المنتج |

عيّن قيمًا دقيقة عندما يلزم إعادة إنتاج الشكل، وقيودًا مرنة عندما يحكمه
المحتوى. مثال أسماء أدوار: `color.text.primary` و`type.body.ar` و
`space.section`؛ اختَر قيمها من الأدلة والمشروع. لا تسلّم أسماء دون قيم،
ولا توزع أرقامًا مستقلة متعارضة في كل شاشة.

افصل اللون الأصلي عن دوره الدلالي. يحدد المشروع معاني النجاح والخطأ والتحذير
والتركيز، مع التباين وإشارات غير لونية. إذا احتجت لونًا وظيفيًا إضافيًا،
سمّه قرار منتج واذكر سببه؛ لا تنسبه للوحة الهوية ولا تُعد تلوين الشعار بسببه.
حدد حالات الألوان لكل مكوّن مستخدم، لا باقة ضخمة من حالات لا وجود لها.

اختَر حجم النص وتباعد الأسطر وفق القراءة الفعلية في اللغتين. افحص ملفات
الخط وأوزانها من الفهرس، ولا تستنتج الوزن من legacy style وحده. فرق توفر
الملف عن توفره في Figma أو المتصفح. خصص fallback عند الحاجة ووضح أثره.
مقاسات الأمثلة التحريرية في دليل الهوية لا تحدد مقياس UI عامًا.

احفظ الشعار بأصله ونسبه ومساحته الآمنة. قياس الرمز المرئي يختلف عن صندوق
الملف. استعمل الرسوم ذات الدقة والتنسيق المناسبين، وحدد crop وموضع النص
خارج مناطق التشويش. اختر أيقونات وظيفية متسقة ومفهومة؛ الأسلوب المرجعي
في الهوية لا يعني توفر مكتبة أيقونات تفاعلية جاهزة.

## Components

المكوّن قرار تصميم وسلوك قابل لإعادة الاستخدام. حدّد له:

- المهمة، التكوين الداخلي، مواضع النص والأيقونة والإجراءات.
- الأنواع والمقاسات المطلوبة، ومتى يستخدم كل نوع.
- الحالات التي تحدث فعلًا: عادي، مرور مؤشر، تركيز، تحديد، انشغال، تعطيل، خطأ.
- المحفز والنتيجة، وطريقة التفاعل بلوحة المفاتيح واللمس.
- الالتفاف والاقتطاع وحدود المحتوى الطويل، مع الوصول للنص الكامل عند الحاجة.
- العربية والإنجليزية والاتجاه والتسمية الميسرة.

افصل الحالات المتزامنة: قد يكون العنصر محددًا ويحمل التركيز في الوقت نفسه؛
لا تترك حالة تلغي وضوح الأخرى. المكوّن المعطل يحتاج تفسيرًا عندما يعجز
المستخدم عن معرفة سبب تعطيله. المرور بالمؤشر وحده لا يكفي لإتاحة إجراء
أساسي على الجوال أو لوحة المفاتيح.

حدد متى تُستخدم صفحة أو لوحة جانبية أو نافذة حوار بناءً على طول المهمة
والسياق والحاجة للمقارنة. عند استخدام حوار، حدد عنوانه وإغلاقه وتركيزه
والعودة إلى العنصر المناسب وأثر الإغلاق على المدخلات.
استخدم مكونات المنصة أو المكتبة القائمة حين تفي بالهدف؛ تخصيص الشكل
لا يقتضي إعادة اختراع سلوك تفاعلي مستقر.

## Responsive behavior

صمم التغير في السلوك والتركيب، لا مجرد تصغير العناصر. اختر نقاط التحول
وفق تعثر المحتوى والنظام القائم، وسجل قيمها كوحدات تنفيذ مناسبة للمنصة.
المقاسات المرجعية للفحص أمثلة اختبار؛ لا تختزل التجاوب في لقطتين جامدتين.

لكل منطقة مهمة، حدد:

| عند تغير المساحة | قرار مطلوب |
| --- | --- |
| التنقل | ما يبقى ظاهرًا، وما ينتقل لقائمة، وكيف تعرف الوجهة الحالية؟ |
| الأعمدة والمجموعات | ترتيب القراءة والتكديس وعرض المحتوى الأقصى والمحاذاة |
| الإجراءات | الالتفاف أو التجميع أو التثبيت، وما يمنع حجب المحتوى والتركيز |
| الجداول | الأعمدة ذات الأولوية وطريقة مقارنة البيانات أو عرض تفاصيلها |
| النماذج | عرض الحقول وتسلسلها وتأثير لوحة المفاتيح والمساعدة والأخطاء |
| الرسوم | التسميات والوسيلة البديلة لقراءة القيم عند ضيق المساحة |

قد تناسب البطاقات بعض بيانات الجداول، وقد تحتاج المقارنة إلى جدول وتمرير
محلي واضح. اختر بحسب المهمة. لا تخف معلومة ضرورية أو إجراء أساسي لمجرد
ضيق الشاشة. افحص العرض المتوسط والمحتوى الطويل والتكبير إضافة إلى المقاسات
الممثلة، ضمن التغطية اللازمة للطلب.

## Visual resolution

المواصفات الدقيقة تحسم: التسلسل، التركيب، الأبعاد والقيود، الخطوط، أزواج
الألوان، المسافات، المكونات، الأصول، النصوص والحالات. عبارات مثل «حديث
وجميل ومتجاوب» لا تكفي لتوجيه التنفيذ.

عند غموض الاتجاه، اختبر شاشة تمثل المشكلة الأصعب المفيدة: قد تجمع نموذجًا
ورسالة خطأ أو بيانات كثيفة ومحتوى مختلطًا. استخدم Figma أو معاينة تنفيذ
ضمن النطاق المتاح. راجع المقياس والكثافة والهوية في العربية والإنجليزية
قبل تعميم قرار بصري مكلف.

أبْقِ قرارات التصميم في [مواصفات المشروع](developer-handoff.md)، ووثّق
أي تعديل مقصود خرج من المعاينة. لا تدّع عرضًا عالي الدقة فعليًا لمجرد
وصفه نصيًا؛ دليل الفحص المرئي في [مراجعة التصميم](design-review.md).
