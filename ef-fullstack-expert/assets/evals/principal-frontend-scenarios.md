# سيناريوهات تقييم سلوك المهارة (Principal Frontend / React)

استخدمها لاختبار المهارة فعليًا بعد أي تعديل: أعط النموذج السيناريو مع المهارة وقارن الإجابة بالمتوقع.
النص الجيد للمهارة لا يثبت السلوك؛ هذه السيناريوهات تثبته. سجّل النتيجة والتاريخ والنموذج.
السيناريوهات المكملة للخادم في `principal-backend-scenarios.md`.

## 1. نتائج بحث خاطئة أحيانًا
**المدخل:** «مربع البحث يعرض أحيانًا نتائج لا تطابق ما كتبته.» مع كود `useEffect` يجلب عند كل تغيير.
**المتوقع:** يشخص سباق استجابات؛ query بمفتاح يحمل النص (أو AbortController مع حارس)، `keepPreviousData`،
debounce كتحسين لا كإصلاح؛ اختبار MSW بتأخير معكوس.
**رسوب:** debounce وحده حلًا، أو `isMounted` flag.

## 2. مستخدم يرى بيانات جهة أخرى لحظيًا
**المدخل:** «بعد تبديل الجهة تظهر بيانات الجهة السابقة ثانية قبل تحديثها.»
**المتوقع:** Critical؛ scope في query keys، remount بالـkey في نفس commit، `removeQueries`/`clear`، إلغاء الطلبات
الجارية، مسح persisted cache والمسودات؛ اختبار بطلب بطيء. يذكر أن الخادم يفوض على أي حال.
**رسوب:** `queryClient.clear()` في useEffect فقط، أو "أضف loading spinner".

## 3. نقل البيانات إلى Redux
**المدخل:** «نريد Redux لكل بيانات التطبيق ليكون منظمًا.» (تطبيق داخلي، 40 شاشة)
**المتوقع:** يفصل حالة الخادم (Query) والـURL والمسودات (RHF) والحالة المحلية؛ يوضح متى يستحق RTK أو Zustand
ولماذا لا هنا؛ ADR بالكلفة.
**رسوب:** يوافق وينشئ slices لنسخ API.

## 4. اعتماد بنقرة مزدوجة وتعارض
**المدخل:** «زر الاعتماد أحيانًا يعتمد مرتين أو يكتب فوق تعديل زميل.»
**المتوقع:** ETag/If-Match و412 مع عرض الأحدث، تعطيل الزر وحارس handler، لا retry للكتابة، idempotency
في الخادم؛ اختبار نقرتين = طلب واحد و412 دون إعادة إرسال.
**رسوب:** debounce على الزر فقط، أو retry تلقائي بعد 412.

## 5. انقطاع الاتصال أثناء الحفظ
**المتوقع:** "نتيجة مجهولة" لا "فشل"؛ إعادة قراءة للتحقق أو Idempotency-Key مرتبط بالمسودة؛ الإدخال محفوظ؛
لا إعادة POST تلقائية.
**رسوب:** رسالة "فشل الحفظ، حاول مرة أخرى" مع إعادة الإرسال بلا مفتاح.

## 6. أخطاء التحقق من الخادم لا تظهر
**المدخل:** ValidationProblemDetails بمفاتيح `Items[1].UnitPrice` و`""`، والنموذج RHF مع field array.
**المتوقع:** تحويل المفاتيح إلى `items.1.unitPrice`، `setError` للحقول الظاهرة، ملخص لما لا يطابق، focus لأول
خطأ، حفظ الإدخال؛ اختبار عقد للمفاتيح الفعلية.
**رسوب:** toast عام بنص الخادم، أو إسقاط الأخطاء غير المطابقة.

## 7. JWT في localStorage
**المدخل:** «نخزن access وrefresh tokens في localStorage لتطبيق React.»
**المتوقع:** BFF بـcookie HttpOnly وantiforgery كافتراض لـEF؛ أو PKCE مع SDK وaccess قصير وrotation؛ يوضح أن
XSS يبقى خطرًا حتى مع التوكن في الذاكرة؛ CSP.
**رسوب:** "استخدم sessionStorage" كحل أمني.

## 8. محتوى HTML من المستخدمين
**المتوقع:** لا `dangerouslySetInnerHTML` بلا DOMPurify بقائمة مسموحة (ويفضل التعقيم عند الحفظ أيضًا)، تحقق
بروتوكول الروابط، CSP وTrusted Types؛ يصنفه Critical في المراجعة.

## 9. صفحة الإدارة بطيئة
**المدخل:** «الكتابة في فلتر لوحة تحتوي 2000 صف متقطعة.»
**المتوقع:** قياس بـProfiler وPerformance panel على production build؛ فلترة في الخادم مع صفحات أو تقليل الصفوف،
colocation للحالة، فصل مكون الصف مع مفتاح ثابت، `useDeferredValue` للعرض، virtualization مع الحفاظ على
الإتاحة؛ لا memo عام قبل القياس.
**رسوب:** `useMemo` و`useCallback` على كل شيء.

## 10. حزمة 2MB
**المتوقع:** تحليل الحزمة بالـsource map/visualizer أولًا، lazy routes، تحميل كسول لمكتبات غير لازمة للعرض الأول،
ميزانية في CI؛ لا تقسيم عشوائي يخلق waterfall.

## 11. SignalR يفتح اتصالين ويضاعف الإشعارات
**المتوقع:** StrictMode + اتصال لكل مكون؛ مدير واحد ref-counted بإيقاف مؤجل، `onreconnected` بلا إزالة يُسجل
مرة واحدة، dedupe بالنسخة، resync بعد reconnect؛ الحدث يبطل الـcache لا يكون مصدر الحقيقة.
**رسوب:** تعطيل StrictMode.

## 12. جدول بإجراءات جماعية
**المتوقع:** عقد page/sort/filter بقائمة حقول مسموحة في .NET، الحالة في URL، `getRowId` ثابت، معنى "تحديد الكل"،
نتيجة لكل عنصر في الإجراء الجماعي، صلاحية لكل صف، تصدير كـjob، إتاحة الجدول.
**رسوب:** جلب كل البيانات وفلترتها في المتصفح.

## 13. Modal غير قابل للوصول
**المدخل:** `div` بـ`role="dialog"` وزر إغلاق `span`.
**المتوقع:** native dialog أو primitive موثوق، focus أولي وحصر وإرجاع، Esc، خلفية inert، عنوان مرتبط، زر حقيقي،
RTL في الـportal؛ اختبار لوحة المفاتيح.
**رسوب:** إضافة `aria-modal` فقط.

## 14. تواريخ ومبالغ عربية
**المدخل:** «تاريخ الاستحقاق يظهر يومًا قبل الصحيح، والأرقام تظهر بالعربية الهندية في جهاز وباللاتينية في آخر.»
**المتوقع:** date-only لا يمر بـ`new Date()`؛ locale صريح `-u-nu-latn-ca-gregory` (أو هجري بقرار)؛ المبالغ نصوص
decimal؛ اختبار قرب منتصف الليل.

## 15. 403 يعيد إلى login في حلقة
**المتوقع:** 401 ≠ 403؛ صفحة "لا تملك صلاحية"، returnUrl نسبي متحقق، refresh single-flight، لا redirect لكل 403.

## 16. ترحيل مشروع CRA بـclass components وRedux thunks
**المتوقع:** جرد، اختبارات رحلات أولًا، Vite، ترقية React وRouter major بخطوات بـcodemods، نقل الجلب إلى Query
شاشة بشاشة، class → function عند اللمس فقط؛ خطة رجوع.
**رسوب:** إعادة كتابة كاملة.

## 17. مراجعة PR
**المدخل:** مكون يجلب في effect بلا إلغاء، `key={index}` لقائمة قابلة للحذف بحقول، `dangerouslySetInnerHTML`
لتعليق، `eslint-disable exhaustive-deps`، `catch { setItems([]) }`.
**المتوقع:** Critical (XSS) ثم High (سباق، key، lint suppression، إخفاء الفشل كقائمة فارغة)؛ لكل نتيجة شرط
الظهور والإصلاح والاختبار؛ لا يغير ما لا يلزم.

## 18. اختبارات هشة
**المدخل:** اختبارات تفحص state داخلي وsnapshots ضخمة وتنتظر `setTimeout(1000)`.
**المتوقع:** استعلامات role/label، MSW بعقود حقيقية، انتظار شروط، اختبار ما يُرسل، Playwright لرحلات قليلة.

## 19. ترقية TypeScript تكسر ESLint
**المدخل:** «رقّينا إلى TypeScript 7 وتوقف typescript-eslint.»
**المتوقع:** يعرف (أو يتحقق) أن 7.0 بلا programmatic API؛ الاسم المستعار `@typescript/typescript6` للأدوات و7 للـ`tsc`؛
لا تعطيل typed linting.

## 20. اختيار نهج لتطبيق داخلي جديد
**المدخل:** «نظام طلبات داخلي لصندوق البيئة بـ.NET، 300 مستخدم، عربي/إنجليزي، إشعارات.»
**المتوقع:** default stack موثق (Vite SPA + BFF + Query + RHF/zod + Router + نظام تصميم EF + i18n + SignalR)
مع البدائل وشروط الخروج، تقدير موسوم، ميزانية حزمة، استراتيجية اختبار ورصد؛ في صيغة ADR.
**رسوب:** Next.js وmicro-frontends بلا مبرر، أو قائمة مكتبات بلا مفاضلة.

## معيار الدرجة

- 10/10 للسيناريو: كل عناصر «المتوقع» حاضرة، لا عنصر «رسوب»، والكود أو القرار قابل للتنفيذ.
- مستوى Principal Frontend: متوسط ≥ 9 ولا سيناريو أقل من 7. مستوى Elite: متوسط ≥ 9.5 ولا سيناريو أقل من 8،
  مكرر على تشغيلين أو نموذجين.
