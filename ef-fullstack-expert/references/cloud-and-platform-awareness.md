# الوعي بالسحابة والمنصات المدارة

اقرأ عند مقارنة الاستضافة المحلية بخدمات مدارة، أو نقل مكوّن إلى سحابة، أو إدارة
الأسرار والهويات بين الخدمات. لا تفترض مزودًا: بنية المشروع والسياسات المعتمدة هي المرجع،
والتوافر الإقليمي والتصنيف والإقامة تُتحقق منها وقت القرار.

## مقابلات المفاهيم بين المنصات

| المفهوم | محلي/Windows | Azure (مثال) | ما يجب التحقق منه في أي مزود |
| --- | --- | --- | --- |
| استضافة الويب | IIS | App Service، Container Apps | runtime المدعوم، scale-out، deployment slots، شبكة خاصة |
| قاعدة SQL Server | SQL Server مُدار ذاتيًا | Azure SQL / Managed Instance | توافق الميزات (SQL Agent، CLR، cross-db)، backups وPITR، HA، الأداء بالمستوى |
| الرسائل | جدول queue / RabbitMQ | Service Bus | الضمانات، DLQ، sessions، الحدود |
| Cache | Redis ذاتي | Azure Cache for Redis | persistence، TLS، eviction، الشبكة الخاصة |
| الملفات | مشاركة SMB | Blob Storage | private endpoints، SAS قصير، lifecycle، immutability |
| الأسرار | ملف محمي بـACL، DPAPI، cert store، Vault | Key Vault | تدوير، صلاحيات، تدقيق الوصول، caching في التطبيق |
| هوية الخدمة | gMSA | Managed Identity | تجنب الأسرار الثابتة بين الخدمات |
| الرصد | Seq/ELK/Grafana/Prometheus | Application Insights / Azure Monitor | OpenTelemetry كطبقة محايدة، الاحتفاظ والكلفة |
| موازنة الحمل | NLB/ARR/F5 | Application Gateway / Front Door | health probes، sticky، WebSockets، TLS termination |

استخدم OpenTelemetry وواجهات .NET القياسية (`IDistributedCache`، `ILogger`، تهيئة
Options) لتقليل الارتباط بالمزود، دون اختراع طبقة تجريد شاملة لكل خدمة سحابية.

## الأسرار والهويات

- الترتيب المفضل: هوية مُدارة (Managed Identity/gMSA) → مخزن أسرار مع تدوير → متغيرات
  بيئة محمية. لا أسرار في الكود أو appsettings المتعقب أو صور الحاويات أو السجلات.
- حمّل الأسرار عبر configuration provider عند البدء مع إعادة تحميل محسوبة، ولا تستدعِ
  مخزن الأسرار في كل طلب.
- وثّق مالك كل سر وتاريخ انتهائه وإجراء تدويره، وأنذر قبل الانتهاء.

## قرار النقل إلى خدمة مدارة

قارن: ما المسؤولية التي تنتقل للمزود (patching، backups، HA) وما الذي يبقى (الفهارس،
الاستعلامات، الصلاحيات، الكلفة)، والقيود (ميزات غير مدعومة، حدود الاتصال، latency من
الخوادم المحلية)، ومتطلبات الإقامة والتصنيف، والكلفة الشهرية مقابل كلفة التشغيل الذاتي
الفعلية. الخدمة المدارة لا تلغي الحاجة لاختبار الاستعادة.

## الكلفة السحابية

الكلفة تتبع الاستخدام: egress، عدد العمليات، الاحتفاظ بالسجلات، المستويات المحجوزة.
قدّر الكلفة الشهرية بافتراضات موسومة، وضع تنبيهات ميزانية، واعتبر السجلات والـtelemetry
بندًا رئيسيًا لا هامشيًا.
