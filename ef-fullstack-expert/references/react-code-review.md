# مراجعة كود React وTypeScript

اقرأ عند مراجعة PR واجهة أو تدقيق مشروع React. نفس مقياس الخطورة في مرجع مراجعة الكود والأمان:
لكل نتيجة الموقع، والمشكلة، **شرط الظهور**، والأثر، والإصلاح (كود)، والاختبار الذي يثبته. لا تغيّر
ما لا يحتاج تغييرًا، ولا تُغرق المراجعة بملاحظات أسلوب قبل الصحة والأمان.

## ترتيب المراجعة

1. الأمان والخصوصية (XSS، tokens، أسرار، قرار أمني في الواجهة، تسرب بين جلسات).
2. صحة البيانات (سباقات، نتائج قديمة، كتابة بلا نسخة، نجاح زائف، فقد إدخال).
3. سلوك React (effects، keys، stale closures، تعديل state).
4. الإتاحة والعربية (focus، labels، RTL، أرقام وتواريخ).
5. الأداء المثبت بقياس.
6. البنية والصيانة.

## قائمة الفحص

**Critical**
- `dangerouslySetInnerHTML` أو `href` من بيانات بلا تعقيم أو تحقق بروتوكول.
- tokens في localStorage، سر في `VITE_*`، returnUrl غير متحقق.
- إظهار بيانات مستخدم سابق بعد تبديل الجلسة (مفتاح cache بلا scope، store عام لا يُمسح).
- قرار صلاحية في الواجهة فقط دون فحص في الخادم.
- كتابة بلا ETag/version على مورد يحرره أكثر من شخص (last write wins خفي).

**High**
- جلب في effect بلا إلغاء أو حارس سباق (نتيجة قديمة تكتب فوق أحدث).
- `retry` لكتابة غير idempotent، أو إعادة إرسال POST تلقائيًا بعد فقد الاستجابة.
- رسالة نجاح قبل استجابة ناجحة، أو `catch` يعرض قائمة فارغة.
- state مكرر لبيانات الخادم مع effect للمزامنة.
- `key={index}` في قائمة تتغير ترتيبًا أو حذفًا مع حالة داخلية (حقول، تحديد).
- تعريف مكون داخل مكون آخر (يعاد تركيبه كل render فيفقد الحالة والـfocus).
- تعطيل `exhaustive-deps` أو `@ts-ignore`/`as` لإسكات خطأ غير مفهوم.
- modal بلا إدارة focus، أو عنصر تفاعلي `div` بلا لوحة مفاتيح.
- مبلغ يُحوّل إلى `number`، أو `new Date('YYYY-MM-DD')` لتاريخ أعمال.

**Medium**
- `useMemo/useCallback` بلا قياس يعقد الكود، أو غيابها حيث يثبت Profiler كلفة.
- Context بقيمة كائن جديدة كل render لشجرة كبيرة.
- مكون أو hook ضخم يمزج الجلب والتحويل والعرض (`useEverything`).
- رسائل مستخدم مكتوبة داخل المنطق، أو نص خادم إنجليزي يُعرض مباشرة.
- استيراد داخلي من feature أخرى، أو shared يعرف feature.
- اختبار يفحص تفاصيل التنفيذ (state داخلي، أسماء دوال) بدل السلوك.

**Low**: التسمية، والتكرار الصغير، وترتيب الملفات.

## أمثلة نتائج

> **High — نتيجة بحث قديمة تطمس الأحدث** `SearchBox.tsx:24` يجلب في `useEffect` عند كل حرف دون
> إلغاء. **يظهر** عندما تصل استجابة "اع" بعد "اعتماد" (شبكة متذبذبة أو استعلام أبطأ). **الأثر:** المستخدم يرى
> نتائج لا تطابق ما كتبه وقد يتصرف عليها. **الإصلاح:** نقل الجلب إلى `useQuery({ queryKey: ['search', q] })`
> مع `placeholderData: keepPreviousData`، أو AbortController في cleanup مع تجاهل النتائج بعد الإلغاء.
> **الاختبار:** MSW يؤخر الطلب الأول 200ms والثاني 10ms؛ تُعرض نتائج الطلب الثاني فقط.

> **Critical — بيانات المستخدم السابق بعد تبديل الجهة** مفتاح `['requests', id]` لا يتضمن الجهة،
> و`queryClient` لا يُمسح عند التبديل. **يظهر** لمستخدم يملك جهتين ويبدل بينهما على نفس الرابط.
> **الأثر:** عرض بيانات جهة لا يحق له رؤيتها حاليًا في الواجهة ولو لحظيًا. **الإصلاح:** scope في كل
> مفتاح، وremount بالـkey، و`removeQueries` للنطاق القديم (المثال الذهبي `sessionScope.tsx`).
> **الاختبار:** `sessionIsolation.test.tsx`.

## كيف تقدم refactoring

- أصغر تغيير يزيل الخطر، ثم تحسينات اختيارية منفصلة. اذكر ما **لم** تغيّره ولماذا.
- اكتب النسخة المحسنة للجزء المعني فقط، مع الاختبار الذي كان سيفشل قبل الإصلاح.
- وضّح trade-off كل اقتراح (حجم، تعقيد، تعلم الفريق).

## ما لا تطلبه في المراجعة

memo عام بلا قياس، مكتبة جديدة لحل محلي، إعادة هيكلة مجلدات في PR إصلاح، تغيير أسلوب يخالف
اصطلاح المشروع القائم.
