# تعدد المستأجرين والعزل بين النطاقات

اقرأ عند تصميم نظام يخدم عدة جهات أو إدارات أو مساحات عمل (workspace)
بعزل بيانات. «المستأجر» في أنظمة الصندوق قد يكون جهة خارجية أو إدارة داخلية
أو مساحة عمل؛ القواعد نفسها تنطبق على أي نطاق وصول.

## اختر نموذج العزل من المتطلبات

| النموذج | مناسب عندما | الكلفة والمخاطر |
| --- | --- | --- |
| Shared DB, Shared Schema (عمود TenantId) | مستأجرون كثيرون، متطلبات عزل عادية | خطأ فلترة واحد يسرب بيانات؛ noisy neighbor؛ استعادة مستأجر واحد صعبة |
| Shared DB, Schema per Tenant | عزل أوضح مع تشغيل مشترك | migrations × عدد schemas؛ plan cache والصلاحيات أعقد |
| Database per Tenant | عزل تنظيمي/تعاقدي، أحجام كبيرة، استعادة وتصدير لكل مستأجر | كلفة وترخيص وتشغيل وmigrations موزعة؛ connection pools متعددة |

يمكن المزج: مشترك للجميع، وقاعدة مستقلة لمستأجر كبير أو حساس. وثّق القرار في ADR
مع متطلبات الإقامة والتصنيف والاستعادة.

## حل المستأجر من مصدر موثوق

- اشتق المستأجر من claim في token تم التحقق منه، أو من host مسجل مسبقًا، ثم
  تحقق من عضوية المستخدم فيه. لا تقبل TenantId من body أو query أو header عميل
  كمصدر للحقيقة.
- ضع `ITenantContext` scoped يُملأ مرة في middleware، وارفض الطلب إن غاب السياق
  في مسار يتطلبه. لا تستخدم static/AsyncLocal بلا ضبط وتنظيف.
- jobs والرسائل: خزّن TenantId في سجل المهمة/الرسالة، وأعد إنشاء السياق داخل
  scope المهمة، وأعد فحص الصلاحية عند التنفيذ.

## افرض العزل في أكثر من طبقة

- EF global query filter على TenantId كخط أول، مع اختبار كل `IgnoreQueryFilters`
  وraw SQL وDapper.
- مفاتيح مركبة تتضمن TenantId في FK والقيود الفريدة، كي لا يشير سجل إلى سجل من
  مستأجر آخر ولا تتعارض قيم فريدة بين المستأجرين.
- SQL Server RLS مع `SESSION_CONTEXT` كخط دفاع إضافي للبيانات الحساسة؛ اضبط
  السياق لكل اتصال مستعار من pool وامسحه، واختبر إعادة الاستخدام.
- authorization على المورد يبقى مطلوبًا داخل المستأجر نفسه (الأدوار والملكية).

## بقية المكونات

- مفاتيح cache وأسماء الملفات/المسارات تتضمن TenantId؛ لا تشارك response cache.
- السجلات والـtraces تحمل TenantId (معرف لا اسم أو PII) لتشخيص مستأجر محدد.
- rate limiting وquotas وحدود الطوابير لكل مستأجر لمنع noisy neighbor.
- feature flags وإعدادات لكل مستأجر بقيم افتراضية آمنة.
- دورة الحياة: إنشاء مستأجر (provisioning قابل لإعادة التنفيذ)، تعطيل، تصدير
  بياناته، حذفها وفق الاحتفاظ، واستعادة مستأجر واحد.

## اختبر

مستخدم من مستأجر A يطلب مورد B مباشرة وعبر البحث والتصدير والمرفقات والـjobs؛
`IgnoreQueryFilters` في مسار إداري؛ اتصال مستعار بعد طلب مستأجر آخر؛ مفتاح cache
بعد تبديل المستأجر؛ unique constraint بنفس القيمة في مستأجرين.
