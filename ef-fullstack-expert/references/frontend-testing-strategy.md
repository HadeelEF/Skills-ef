# استراتيجية اختبار الواجهة

اقرأ عند تحديد ماذا نختبر في ميزة واجهة، أو كتابة اختبارات React، أو مراجعة اختبارات ضعيفة.
اختبارات الخادم في مرجع استراتيجية اختبار الـBackend. الأمثلة المختبرة في `golden-react-feature/tests`.

## ماذا نختبر وأين

| المستوى | الأداة | ما يثبته | ما لا يثبته |
| --- | --- | --- | --- |
| typecheck + lint | tsc، ESLint | العقود والأنواع وقواعد hooks | السلوك |
| دوال خالصة | Vitest | تحويلات (مفاتيح الأخطاء، المبالغ، الصلاحيات المشتقة) | التكامل |
| مكون/ميزة | Testing Library + MSW + jsdom | سلوك المستخدم مع عقود API ممثلة: حالات، أخطاء، سباقات، إتاحة أساسية | الخادم الحقيقي، CSS، المتصفح الحقيقي |
| عقد | OpenAPI diff أو اختبار schema ضد استجابات حقيقية | تطابق الواجهة والخادم | السلوك |
| رحلة | Playwright على بيئة منشورة | cookies/CSRF، تفويض حقيقي، حفظ وإعادة قراءة، RTL الفعلي، keyboard | كل الحالات الطرفية (مكلفة) |
| بصري | Playwright snapshots ببيئة مثبتة | انحراف التصميم في الاتجاهين | السلوك |
| إتاحة | axe داخل Playwright + اختبارات role/label | مخالفات آلية | الامتثال الكامل |

الثقل الأكبر على اختبارات الميزة مع MSW (سريعة وتمثل الاستخدام)، وقليل من رحلات Playwright للمسارات
الحرجة، وعقد يمنع الانحراف.

## قواعد كتابة اختبار ميزة

- استعلم بما يراه المستخدم: `getByRole(name)`، `getByLabelText`، `toHaveAccessibleDescription`. إذا لم تجد
  العنصر بالدور والاسم فغالبًا مشكلة إتاحة لا مشكلة اختبار.
- `userEvent.setup()` لا `fireEvent` للتفاعل.
- MSW بعقود حقيقية: ProblemDetails بـcontent type الصحيح، ETag، تأخير، `HttpResponse.error()` للشبكة.
  اجعل الطلبات غير المعالجة خطأ (`onUnhandledFrame: 'error'` في MSW 3).
- اختبر ما يُرسل (headers، body، عدد الطلبات) لا فقط ما يُعرض: If-Match، Idempotency-Key، شكل الأمر.
- مخزن حالة صغير داخل الاختبار يحاكي الخادم ليثبت إعادة القراءة بعد الكتابة.
- استخدم الـproviders الحقيقية (QueryClient بإعدادات المشروع) مع تعطيل retry للقراءة فقط، واختبر سياسة
  retry كوحدة مستقلة.
- لا snapshots ضخمة للـDOM، ولا فحص state داخلي أو استدعاء hooks مباشرة إلا للـhooks العامة المعزولة.
- انتظر نتيجة ذات معنى (`findBy`، `waitFor` على شرط)، لا `sleep`. وقت ثابت بـfake timers عند منطق زمني
  (مع `userEvent.setup({ advanceTimers })`).

## الحالات التي تميز الاختبار الجيد

لكل ميزة كتابة اختبر حسب ما ينطبق: النجاح مع إعادة القراءة؛ تحقق العميل يمنع الطلب؛ أخطاء الخادم على
الحقل الصحيح؛ 409/412 دون إعادة إرسال؛ نتيجة مجهولة (الخادم نفّذ وفُقدت الاستجابة) مع اتصال وبدونه؛ نقرتان
= طلب واحد؛ لا صلاحية = لا زر (والخادم يرفض)؛ 404 و403 كما تقرر السياسة؛ تبديل جلسة بطلب بطيء؛ استجابة
قديمة بعد أحدث؛ حدث realtime مكرر.

## اختبار الصلاحيات

مصفوفة: الأدوار × الإجراءات × حالة المورد. في الواجهة اختبر أن `allowedActions` تتحكم بالظهور. **الإثبات
الحقيقي في الخادم:** اختبارات تكامل API بمستخدم بلا صلاحية ومن نطاق آخر. Playwright يتحقق من رحلة مستخدم
محدود الصلاحية واحدة على الأقل.

## Playwright

- storageState من project إعداد يسجل الدخول عبر IdP اختبار أو BFF test login محمي ومتاح في بيئة الاختبار فقط.
- بيانات مزروعة لكل اختبار أو API إعداد؛ لا اعتماد على ترتيب الاختبارات.
- `retries: 0` افتراضيًا محليًا؛ اختبار متذبذب خلل يُحقق فيه. trace عند الفشل دون tokens.
- `locale: 'ar-SA'` وفحص `dir` وتشغيل اللغتين للرحلات الأساسية.
- axe (`@axe-core/playwright`) على الصفحات الرئيسية بقواعد WCAG المطلوبة، مع مراجعة يدوية للوحة المفاتيح.

## سلّم بدقة

اذكر ما شُغّل فعلًا: typecheck، lint، عدد الاختبارات الناجحة، build، وما لم يُشغَّل (Playwright بلا بيئة).
نجاح اختبارات MSW لا يثبت تفويض الخادم أو سلوك SQL.
