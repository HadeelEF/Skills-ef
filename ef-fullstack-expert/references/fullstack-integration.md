# تنفيذ Full Stack

## احسم حدود الواجهة والخادم

حدد هل التطبيق Razor Pages أو MVC أو HTML/JavaScript أو React، ثم
اقرأ مراجع التنفيذ الداخلية من فهرس المهارة لـReact/TypeScript أو
HTML/CSS والـrendering والإتاحة والاختبارات، مع الحفاظ على تقنية المشروع.
تولّ الواجهة والخادم بنفسك؛ الاستعانة بتخصص Frontend إضافي اختيارية.
اقرأ مواصفات المشروع وتسليم UX المعتمد، وef-brand-guidelines عند العمل
البصري لصندوق البيئة. حل أسماء المهارات من البيئة المتاحة؛ لا تعتمد
على مسارات تثبيت شخصية. أكمل العمل المستقل عند غياب مرجع مساند.

احترم framework الموجود. لمشروع جديد اختر صفحات خادمية أو SPA أو SSR/SSG وفق طبيعة
المحتوى والدخول وSEO والاستضافة؛ راجع توفر runtime المطلوب. لا تضف
خادم Node إلى بيئة IIS ثابتة دون معالجة طريقة تشغيله ونشره.

نظم الواجهة حسب الميزات مع حدود للمكونات والبيانات والعقود. افصل حالة
الخادم عن حالة الواجهة المحلية. لا تنشئ store عامًا لكل شيء أو تكرر
cache الخادم في stores متعددة. اجعل ملكية الحالة ومصدر الحقيقة واضحين.

اربط التنظيم بين الطرفين دون فرض تطابق مجلداتهما: backend feature تملك
use case وقواعده، وfrontend feature تملك رحلة المستخدم وعرضها، وAPI هو
العقد بينهما. قد تجمع شاشة أكثر من use case أو module؛ لا تجعل ذلك
مبررًا لكشف entities الداخلية أو ازدواج business policy.
حدد جذور التطبيقات داخل المستودع ومشاريع/حزم العقود المستخدمة فعلًا،
ومكان client generation وbuild assets واختبارات التكامل. اجعل البناء
والنشر لكل طرف واضحين؛ monorepo لا يستلزم نسخة مشتركة لكل أداة أو اعتماد.
عند تغيير عقد API حدّث المستهلك والأنواع والتحويل ورسائل الأخطاء معًا،
وافحص backward compatibility إذا لم يُنشر الطرفان في الوقت نفسه.

للصفحات الخادمية تتبع .cshtml وPageModel/controller ثم خدمة الأعمال
والبيانات، وأضف JavaScript/jQuery للتفاعل المطلوب. حدد عقد كل form أو
AJAX: action/handler، وnames/prefixes، وencoding، وantiforgery، ونوع
النتيجة والأخطاء. يمكن أن تتشارك صفحة وAPI في use case دون loopback HTTP.
حدد CSS framework وخط بناء assets قبل تنسيق المكونات، وافحص الناتج
المنشور إلى wwwroot. Node وقت البناء لا يفرض runtime Node للإنتاج.

## اربط عقدًا حقيقيًا

حدد مصدرًا واحدًا لعقد API. استخدم generated client من OpenAPI عندما
يقلل الانحراف، أو client صغيرًا typed عندما يناسب النطاق. تحقق من JSON
عند حدود غير موثوقة؛ TypeScript لا يتحقق من بيانات الشبكة وقت التشغيل.

طابق null/undefined والقيم الاختيارية وenums والتواريخ والمبالغ. انتبه
لدقة JavaScript number مقابل long/decimal؛ اختر تمثيلًا متفقًا عليه.
افحص base URL والـproxy والـcookies/headers والـCORS عبر البيئات، دون
تضمين سر في متغير بيئة يرسل إلى المتصفح.

طبق آلية الدخول المعتمدة وحالات 401 و403 وانتهاء الجلسة. لا تسمح للواجهة
بتحديد permissions أو workspace access الموثوقين للخادم.

## أكمل رحلة المستخدم

- نفذ loading/empty/error/success وحالات إعادة المحاولة وغياب الاتصال
  متى كانت ذات صلة. لا تُظهر رسالة نجاح قبل نجاح العملية الحقيقية.
- اربط أخطاء الحقول وأخطاء قواعد الأعمال بعناصر مفهومة. احفظ مدخلات
  المستخدم عند فشل الطلب؛ عالج منع التكرار في الواجهة والخادم حسب الحاجة.
- بعد mutation، حدث أو أبطل cache المناسب، وافحص أن القراءة تعكس الحفظ.
  في optimistic UI صمم rollback والتعارض؛ لا تخف فشل الخادم.
- في Razor/MVC أعد عرض أخطاء النموذج وبيانات الاختيارات عند الفشل،
  واستخدم PRG أو نتيجة AJAX المتفق عليها عند النجاح. حافظ على lifecycle
  للنماذج والـpartials وplugins دون مضاعفة الأحداث أو حذف مدخلات المستخدم.
- أدر cancellation وطلبات البحث المتلاحقة حتى لا تطمس نتيجة قديمة
  نتيجة حديثة. لا تكرر طلبات بسبب Effects أو subscriptions غير مضبوطة.
- اعرض تعارض version/ETag بوضوح مع إعادة تحميل أو إجراء مناسب، دون
  إعادة إرسال تلقائية تمسح تغييرات الآخرين.
- افحص RTL/LTR، والنص المختلط والأرقام والتواريخ، والتنقل بلوحة المفاتيح،
  والتسميات والتركيز والجداول والنوافذ. استخدم CSS logical properties
  وقواعد الهوية والأصول المعتمدة.

## اختبر الأطراف معًا

شغل رحلة ممثلة: الدخول، وقراءة بيانات مسموحة، والتعديل أو الإنشاء،
ثم إعادة القراءة/تحميل الصفحة للتأكد من الاستمرار. افحص المنع والفشل
والتحقق من المدخلات بحسب المخاطر. اختبر API مباشرة لتأكيد صلاحياته.

عند توفر متصفح، شاهد الواجهة وافحص console/network وسلوك التفاعل
والتجاوب؛ نجاح build وحده لا يثبتها. استعمل الأدوات المتاحة وفق قواعدها.
إذا كان الخادم أو قاعدة البيانات mock، سمّ حدود التحقق بوضوح.
في Razor اختبر HTTP filters وantiforgery وbinding، وفي jQuery اختبر
إعادة فتح modal واستبدال partial. افحص أصناف Tailwind وBootstrap في
production assets واتجاهي العرض عند انطباقهما.
