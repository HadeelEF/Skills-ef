# تحويل التصميم إلى كود ومطابقة Pixel-perfect

اقرأ عند طلب تنفيذ Figma أو screenshot أو تصميم معتمد بدقة، أو إصلاح
اختلافات بصرية. استخدم مع مرجع التنفيذ البصري والإتاحة، ومعمارية React
أو Razor/HTML بحسب المشروع. المقصود دقة قابلة للملاحظة في ظروف محددة،
لا وعد بتطابق كل pixel عبر جميع أنظمة التشغيل والمتصفحات.

## ثبت مرجع القبول وظروفه

- حدد المرجع المعتمد وإصداره وframe/صفحة/حالة، والمقاسات المستهدفة
  واللغة والاتجاه والثيم والبيانات. ميز صورة viewport عن full-page أو
  crop؛ لا تستنتج CSS viewport من عدد pixels في صورة مجهولة DPR.
- عند وجود Figma اقرأ المهارة المتاحة المناسبة لـdesign-to-code قبل
  أدواتها، واتبع متطلبات الأداة. استخرج layout/constraints وvariables
  وcomponent variants والأصول، وافحص screenshot للمرجع الفعلي أيضًا.
  لا تفترض توفر connector أو صلاحية الملف، ولا تخترع قياسات لم تُقرأ.
- في screenshot حلل الأبعاد والمحاذاة والتكرار والخط والأصول بما تسمح
  به الدقة. سجل ما استنتجته؛ الصورة لا تحدد behavior أو responsive rules
  لكل الأحجام. استخرج النص بدل تحويل الشاشة كلها إلى صورة داخل الصفحة.
- ميز مواصفة معتمدة عن مثال إلهام. في طلب المطابقة لا تبدل الهوية
  والتخطيط بدافع «تحسين» لم يُطلب. استخدم أصول EF الموثقة؛ إذا تعارض
  مرجعان مؤثران احسم المرجعية مع المستخدم بعد إنجاز العمل المستقل المتاح.
- إذا لم يوجد تصميم، قدم تصميمًا مقترحًا مناسبًا للمنتج مع افتراضاته؛
  لا تدّعِ مطابقته لمرجع غائب. اطلب الأصل المفقود فقط عندما يمنع الدقة.

## حوّل القياسات إلى قواعد ومكونات

| ما تفحصه في التصميم | ما تثبته في الكود |
| --- | --- |
| page shell وcolumns والمحاذاة والحواف | max-width، grid/flex، gaps وpadding وحدود الانكماش |
| typography والتفاف الأسطر | font file/weight/size/line-height وعرض النص واللغة |
| hierarchy وcolors وsurfaces | semantic tokens وvariants في نظام التصميم |
| icons والصور والشعار | asset صحيح، viewBox/نسبة أبعاد وحجم بصري وcrop مناسب |
| fields/buttons/tables/overlays | component contracts وحالات التفاعل والدلالات |
| اختلاف frames ومقاسات الحاوية | قواعد responsive مثبتة أو افتراض معلن للحالات الناقصة |

راجع الخط قبل تعديل عشرات الهوامش؛ اختلاف font metrics قد يغير كامل
التخطيط. تحقق من تحميل الملف والوزن الفعلي ومن fallback وsynthetic bold.
طابق line-height وارتفاع عناصر التحكم والمحاذاة، ولا تقص التشكيل العربي
أو تثبت ارتفاع النص لإخفاء الاختلاف. استخدم أصولًا مخدمة من التطبيق،
ولا تعتمد على رابط جهاز محلي أو مسار مهارة في CSS المنشور.

ابنِ primitives وcompositions المناسبة، واربط states بالبيانات الفعلية.
استخدم tokens/variants مشتركة عند التكرار، مع استثناء محلي عندما يلزم
القياس الدقيق. لا تجبر قياس المرجع على أقرب spacing افتراضي في framework.
حافظ على التدفق والتجاوب؛ absolute positioning مناسب لعنصر موضعي، وليس
آلية نسخ شاشة كاملة. لا تغير نصًا أو تحذف خطأ نموذج لتحسين التشابه.

## نفّذ دورة مشاهدة وتصحيح

1. شغّل route الفعلي في البيئة المصرح بها، وتأكد من الصفحة والبيانات
   وحالة التفاعل. افتح المتصفح عبر الأداة المناسبة وتعليماتها، لا صورة mock.
2. طابق viewport بوحدات CSS وDPR والـzoom واللغة والثيم والـscroll والحالة.
   انتظر جاهزية المحتوى المطلوب والخطوط والصور؛ document.fonts.ready
   مفيد لكنه لا يثبت وحده أن الخط المقصود لم يستبدل بـfallback.
3. التقط screenshot وافتحها للفحص. قارن جنبًا إلى جنب أو overlay/diff
   في بيئة متكافئة. حافظ على origin وscale والـcrop؛ لا تمدد صورة لتخفي
   فرق عرض، ولا تقارن crop مرجعيًا بصورة full-page غير محاذاة.
4. سجل فروقًا محددة ومواقعها، ثم أصلح بالترتيب: shell/geometry، والخط
   والتفافه، ثم spacing وأحجام المكونات، ثم الألوان والحدود والظلال والأيقونات.
   عدّل السبب في token/component/constraint بدل تراكم overrides متعارضة.
5. أعد الالتقاط والفحص بعد التصحيح؛ افحص أثر token المشترك في المكونات
   المتأثرة. كرر للفروق المؤثرة حتى تستوفي معايير المرجع والنطاق.

## اجعل المقارنة عادلة وقابلة للتكرار

ثبت browser/OS/fonts وfixtures والوقت والعناصر المتحركة عندما يلزم
visual regression. وثق أي mask لمنطقة ديناميكية غير محل الفحص؛ لا
تخفِ نصوصًا أو controls أو أخطاء فعلية لتقليل diff. لا تقبل baseline
جديدة تلقائيًا ولا توسع tolerance حتى تختفي المشكلة.

استخدم حدود قبول مناسبة للمشروع والمكون، وراجع الصورة نفسها. نسبة
اختلاف pixels لا تثبت وحدها جودة الواجهة، وفروق anti-aliasing لا تعادل
زرًا مفقودًا أو انزياح layout. لا تعلن نسبة مطابقة أو «Pixel-perfect»
متحققًا دون مقارنة فعلية ومعيار معلن؛ اذكر الفروق المقصودة أو المتبقية.

## احمِ السلوك والتجاوب أثناء المطابقة

اختبر العرض المرجعي والعروض المتوسطة والضيقة التي يتطلبها المنتج، ونصوصًا
طويلة وRTL/LTR وحالات loading/empty/error/focus/disabled المناسبة.
في غياب مرجع جوال اشتق قواعد ملائمة وسمها افتراضًا؛ لا تدّعِ اعتمادها.
احفظ keyboard وfocus وzoom/reflow وإتاحة الرسائل؛ وثق أي معالجة لازمة
لتعارض واضح بين التصميم وإتاحة الاستخدام دون إخفاء المشكلة.

## سلّم دليلًا بقدر المهمة

قدم ملخص المرجع والحالة والمقاسات التي فُحصت، وروابط اللقطات عند إتاحتها،
وأهم الفروق المصححة والمتبقية. فرّق «نفذت وفق المواصفات» عن «قارنت بصريًا»
وعن «اختبرت التفاعل». عند غياب المتصفح أو الأصل، أكمل الكود المتاح
بأفضل تقدير وصرح بأن المطابقة البصرية لم تتحقق بعد؛ لا تسجلها كنجاح.
