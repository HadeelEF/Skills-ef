# التتبع والتغيير والتدقيق

## المصدر المرجعي وخط الأساس

حدد أين يعيش كل نوع معلومات ومن يحدثه. استخدم المعرّفات وروابط الأقسام لإعادة الاستخدام، لا نسخ النص الكامل. خط الأساس لقطة ذات إصدار وحدود وسلطة اعتماد موثقة؛ لا تجعله حظرًا للتطوير التدريجي.

حالات الوثيقة: مسودة، جاهز للمراجعة، معتمد بدليل. فرّق مراجعة تحليلية عن اعتماد أعمال، وافصل جاهزية وحدة عن باقي النظام. احفظ سجل تغيير مختصر: ماذا ولماذا ومن طلب وماذا تأثر. لا تدعِ اعتمادًا لمجرد أن المهمة اكتملت.

## سلسلة التتبع

لبناء RTM تفصيلية اتبع [هندسة التتبع](traceability-engineering.md): علاقات محددة المعنى والاتجاه والنسخة، وتغطية مسارات كاملة/جزئية، مع فصل Test Case عن Test Run. تحقق للأمام والخلف، ولا تورّث نجاح اختبار قديم إلى سلوك تغيّر.

هدف ← قدرة/عملية ← متطلب ← Use Case أو Story ← تصميم/تنفيذ موجود ← معيار قبول/اختبار. أنشئ الروابط الموجودة فقط؛ لكل خانة غائبة استخدم «غير موجود بعد» أو «غير متاح» أو «خارج النطاق» مع سبب. وجود معيار قبول ليس اختبارًا منفذًا. الربط بملف كود دليل أثر تنفيذ، وليس إثبات نجاح.

قياس التغطية عند فائدته: اذكر المقام (المتطلبات داخل النطاق ذات النسخة المحددة) والبسط ونوع التغطية (مصدر/قبول/تصميم/اختبار منفذ). لا تجمعها في نسبة واحدة مضللة ولا تجعل 100% روابط حكمًا بجاهزية المنتج.

إذا كررت وثيقتان قوائم تعلنان التغطية الكاملة للعلاقة نفسها، طابق مجموعات المعرّفات في الاتجاهين؛ تساوي الأعداد وصحة الروابط الموجودة لا يكشفان رابطًا ساقطًا. فضّل خريطة تتبع مرجعية واحدة وإحالات إليها، ولا تفرض تماثلًا على قوائم مختارة معلنة بأنها جزئية.

## تحليل أثر التغيير

للمراجعة بين نسختين احفظ خريطة مصير المعرفات: محفوظ/معدل/مقسم/مدمج/مسحوب بمصدر. فرقُ الفاعل أو «و/أو» أو الاستثناء أو تاريخ النفاذ تغيير سلوك، ولو بقي عنوان المتطلب نفسه. يمكن لفاحص السجل مع --baseline كشف تغيرات وإحالات تحتاج مراجعة؛ لا يثبت الإذن أو كفاية معالجة الأثر.

1. سجل الطلب ومصدره وتفويضه والسبب، والنص السابق والمستهدف.
2. احصر المعرّفات المتأثرة مباشرة وعبر الاعتماديات: العمليات، الصلاحيات، الحالات، القواعد، البيانات، التكامل، التقارير، الإشعارات، الملفات، الجودة، الانتقال، التصميم والاختبار والإصدار.
3. حدد أثر التوافق والطلبات القائمة أثناء الانتقال، وأثر السلوك خارج المسار السعيد.
4. ميّز التحديث المصرح عن قرارات السياسة غير المحسومة. نفّذ المستقل، واكتب المقترح المؤثر بصفته المقترحة دون تفعيله كسياسة معتمدة.
5. حدث المرجع أولًا، ثم الإحالات وBacklog والقبول وUAT وسجل القرار. حافظ على المعرّفات؛ سجل سبب أي إلغاء أو تقسيم.
6. أعد فحص الروابط والاتساق والمعرّفات وقائمة الطلب الأصلية والفرق النهائي. لا تعدل ملفات خارج التفويض.

راجع أيضًا مصدر كل حكم أضيف أثناء التفصيل: هل هو منصوص، أم لازم عن حكم مثبت، أم خيار تحليلي؟ وسم الوثيقة كلها «مسودة» لا يكفي لتصحيح نسبة خيار جديد إلى قرار معتمد. احتفظ بصفة الاقتراح في المصدر المرجعي والإحالات ومعايير القبول المتأثرة دون تعطيل التغييرات المؤكدة.

## منهجية التدقيق

ابدأ بتحديد النسخة والنطاق والملفات التي قرأتها وحدود الوصول. حوّل طلب المستخدم ومصادره إلى قائمة تغطية، ثم راجع:

| البعد | سؤال التدقيق |
|---|---|
| التغطية | هل كل طلب موجود، مؤجل بقرار، مستبعد بمصدر، أم مفقود؟ |
| الهيكل | هل يبدأ بالهدف والحدود ثم القدرات والسلوك ويستخدم إحالات واضحة؟ |
| المصطلحات والهوية | هل التعريفات والمعرّفات والإصدارات متسقة وغير معاد استخدامها؟ |
| التعارض والتكرار | هل توجد قواعد أو نسخ تختلف؟ وما مصدر السلطة؟ |
| السلوك | هل الأدوار والنطاق والحالات والانتقالات والاستثناءات مكتملة بقدر المخاطرة؟ |
| البناء والاختبار | هل يمكن التنفيذ والتحقق دون ابتكار سياسة؟ |
| الجودة | هل المقاييس والظروف وطريقة القياس ذات مصدر؟ |
| الأدلة | هل الموثق متسق مع المطلوب والكود والاختبارات، مع التصنيف الصحيح؟ |
| اليقين | هل الاقتراحات والافتراضات والقرارات المفتوحة مميزة؟ |
| التسليم | هل يستطيع المستلم بدء عمله، وما الذي يمنع أي جزء؟ |

لكل ملاحظة اكتب الموقع/الدليل والوصف والأثر والأولوية ومبررها والتصحيح والحالة. أولويات إرشادية: حرج لقرار سلامة/وصول أو فقد مطلب جوهري؛ عالٍ لتعطيل عملية/سلوك رئيسي؛ متوسط لنقص يسبب اختلاف تنفيذ محدود؛ منخفض لتحسين وضوح لا يغير السلوك. كيّف التصنيف لأثر المشروع، ولا تساوِ ملاحظة تحريرية بتسرب بيانات.

عند طلب الإصلاح، أصلح ضمن التفويض ثم تحقق؛ لا تسلم تقريرًا فقط. سجل «عولج وتم التحقق» أو «عولج ولم يمكن التحقق» أو «قرار مطلوب» أو «خارج النطاق». لا تخفض شدة الملاحظة لتبدو الوثيقة جاهزة.

## الجاهزية والإنهاء

لتقييم متسق استخدم [معايير التحقق](validation-and-quality.md). وجود قالب أو مصطلح لا يثبت اكتمال القدرة، وطلب درجة مستهدفة لا يبرر رفع الدرجة دون إغلاق فجواتها. ركز المراجعة على المخاطر والأجزاء المتغيرة، واربط كل عائق بخطوة تزيله بدل تكرار اختبارات لا تضيف دليلًا.

احكم على جاهزية النطاق التالي بأدلة: مصدر وهدف ونطاق واضح؛ تغطية الطلب؛ قواعد وصلاحيات وحالات معلومة؛ قبول يمكن تنفيذه؛ مسائل حرجة لها حسم أو نطاق معزول بوضوح؛ إحالات صحيحة؛ بيانات الاعتماد صادقة. يمكن القول «جاهز لمراجعة الأعمال في الوحدات أ وب؛ تفصيل التكامل ينتظر…». لا تقل «10/10» أو «جاهز بالكامل» دون معيار وأدلة محددة.


## التتبع بين الوثائق وBacklog وLinear

حدد ملكية الحقول قبل التحديث: أين مرجع السياسة والسلوك، وأين القبول، وأين ترتيب التنفيذ وحالته؟ احتفظ بمعرف المتطلب ومعرف عنصر Backlog ومعرف/رابط Linear الفعلي بدل استبدال أحدها بالآخر. عند التقسيم وزع التغطية والقبول على الأبناء واحفظ الأصل وسبب التغيير؛ عند التجميع لا تسقط الاستثناءات أو الجودة المشتركة.

راجع المتطلبات بلا عناصر، والعناصر بلا هدف/مصدر، وأي دور أو حالة أو NFR لم تعد مغطاة بعد إعادة الترتيب. التغطية الدلالية لا تساوي عدد الروابط، واكتمال تذكرة لا يثبت اعتماد أعمال أو نجاح UAT. ميّز اقتراح التحديث عما حُفظ ثم قرئ فعليًا من الأداة، وحافظ على سجل الفشل الجزئي والقرارات. إجراءات المطابقة والكتابة الآمنة في مرجع Linear.
