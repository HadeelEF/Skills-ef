# التحقق ومعايير الجودة

استخدم عندما تتعدد الوثائق والعناصر أو يُطلب تدقيق أو تقييم. الفحص يخدم قرار جاهزية محدد، ولا يحل محل اعتماد أعمال أو تشغيل نظام. لا تنشئ حزمة فحوص لتغيير تحريري صغير.

## حد جودة قابل للتقييم

| المحور | دليل جودة قوي | ما يمنع إعلان الاكتمال |
|---|---|---|
| الطلب/الاستثمار | نوع ودليل ومسار وبدائل وقرار وسعة/فجوات ومنفعة | جمع التمويل والجدولة في قرار واحد أو أرقام مختلقة |
| الاستنباط | تمثيل أطراف وحالات، أدلة وتوليف وتأكيد فهم | مقابلات أو توافق لم يحدثا، أو تجاهل استثناء مؤثر |
| الاكتشاف | قرار وأدلة ومعارضات وبدائل وافتراضات وتجربة تغير القرار | تحويل تفضيل حل إلى حاجة مؤكدة أو فرضيات إلى نتائج |
| العملية وSwimlane | رسم وجدول بمعرفات ومسؤوليات وحراس ونهايات متسقة | جمع ينتظر فرعًا غير منشط أو عودة مبهمة أو مسار غير موثق |
| أدوات النمذجة | صيغة مطلوبة قابلة للتحرير، هوية عناصر محفوظة، قراءة نتيجة وفحص عرض عند توفره | رابط لوحة مختلق أو صورة بوصفها ملفًا أصليًا أو ادعاء تنفيذ من الرسم |
| هندسة وتحسين العمليات | حدود وقياس وسعة وتشخيص وبدائل وخطة تجربة وضوابط ومتابعة | أتمتة لا تعالج الاختناق، خلط الوقت بالوفر النقدي، أو إعلان تحسن بلا قياس |
| Use Cases | هدف وحدود ومسار مرقم وفروع مرتبطة وضمانات ونتائج | نهاية تناقض أثرًا خارجيًا أو إخفاء فحص مطلوب في شرط سابق |
| RTM | اتجاه ومعنى ونسخة للعلاقة وفصل مقاييس التغطية وأدلة التشغيل | عد صفوف مكررة أو رابط جزئي كتغطية كاملة أو اختبار سابق كقبول جديد |
| تعريف المنتج | حاجة ورؤية واختيارات وتجارب وقياس وخارطة | حل مفترض بلا دليل أو وعد موعد بلا تقدير |
| الوثائق | عقد ملكية معلومات، متطلبات ومعرّفات وقبول وروابط | تكرار متعارض أو سياسة ضمنية بلا مصدر |
| التحليل المؤسسي | حالات وصلاحيات وبيانات وتكامل وفشل متسقة | نهاية غير قابلة للوصول أو كشف عبر قناة أخرى |
| نماذج النظام | حدود ولغة وهوية بيانات وثوابت وعقود وسيناريو متسق عبر النماذج | خلط قبول الاستلام بالتنفيذ أو الحالة التجارية بحالة المزامنة أو التغيير الرجعي للسياسة بلا مصدر |
| ممارسة Scrum | هدف وقرارات فريق وجودة وفحص وتكيف، وتمييز القاعدة عن الممارسة الاختيارية | فرض مهام أو نقاط، أو احتساب غير Done منجزًا، أو جعل Review بوابة إصدار تلقائية |
| إدارة المنتج | حدود وتفويض وفرص ومقايضات وقياس وقرارات دورة حياة مترابطة | قائمة خصائص دون اختيار، أو جدوى مختلقة، أو قياس تبنٍ يستبعد القناة التي تكمل الخدمة |
| Backlog/التسليم | شرائح قيمة وتغطية واعتماديات وجاهزية صادقة | عناصر يتيمة/دورات اعتماد أو تقديرات مفروضة |
| Linear | هوية ومطابقة وحفظ محتوى وعلاقات وقراءة نتيجة | ادعاء كتابة من خطة، أو إعادة إنشاء بعد رد ملتبس |
| المنفعة | مقام وخط أساس ومالك ومصدر وقرار مراجعة | اعتبار نشاط الفريق أو مجرد الاستخدام قيمة نهائية |
| التسليم للتطوير بالذكاء الاصطناعي | شريحة ومراجع بإصدارات وأمثلة قبول مستقلة وجاهزية لكل نشاط | اختبار يكرر خطأ التنفيذ أو تفاصيل تقنية مختلقة أو ضوابط مؤجلة |
| الخدمة عبر القنوات | نتيجة مستفيد وتسليم مسؤولية وتعثر وهوية حالة وصلاحيات | اعتبار إرسال العمل قبولًا له أو إغلاق التذكرة اكتمال خدمة |
| قبول الجودة | مجتمع ونافذة وظروف ومقياس وعتبة بمصدر ونتيجة منفصلة | متوسط بدل مئين أو إخفاء الفشل أو استعادة معلنة دون دليل |
| الصيغة | عربية ومصطلحات متسقة، وفحص مرئي للصيغ المطلوبة | اعتماد RTL من ضبط خاصية دون رؤية المخرج |

إذا طُلبت درجة: عرف النطاق والأوزان والأدلة. 9/10 مستوى قوي يستلزم إجراءً قابلًا للتنفيذ ومخرجًا مترابطًا ومراجعة أو تطبيقًا مناسبًا مع فجوات محددة؛ لا تمنحه لمجرد ذكر الإطار. افصل درجة جودة الحزمة عن ثقة الأداء الفعلي. 10/10 ليست وعدًا بصحة كل مشروع. لا ترفع الدرجة لأن المستخدم حدد هدفًا؛ حسّن السبب وأعد التحقق.

## مراجعة مترابطة بقدر المخاطرة

اختر رحلة ذات قيمة وبديلًا ومنع صلاحية وفشل تكامل/تزامن عند الصلة. تتبعها من الهدف إلى المصدر والقواعد والحالات والمتطلبات والقبول وBacklog وUAT. غيّر افتراضًا أو سياسة في ذهنك وحدد كل أثره ثم قارنه بالتتبع الموثق. افحص كذلك طلبًا صغيرًا للتأكد من عدم تضخيم المخرجات.

إن تغيرت وثيقة سابقة، قارن مع خط أساسها: لا طلب سقط ولا هوية أعيد استخدامها ولا اقتراح أصبح معتمدًا أثناء النقل. راجع الجاهزية محليًا؛ نقص سياسة قد يحجب عنصرًا ويسمح بآخر. وثق ما فُحص وما تعذر وما هو خارج العينة.

## فاحص Markdown

شغل scripts/check_requirements.py بوسيط ملف أو مجلد و--json عند الحاجة. يدعم تعريفات المعرفات أول عناوين Markdown والروابط المحلية البسيطة. دعم المراسي والأنماط موضح في --help؛ لا يعالج تعريفات الجداول أو يغطي دلالة المتطلبات. النتائج الخالية من أخطاء لا تعني وجود معرفات فعلية أو كفاية القبول.

## فاحص السجل المنظم

شغل: python3 scripts/check_analysis.py PATH.json. استخدم --strict فقط إذا أردت خروجًا غير صفري للتحذيرات أيضًا. الأداة قراءة فقط، مكتبتها Python القياسية، وتعيد JSON. يفيد الفهرس للمتطلبات الموجودة في الجداول والعناوين معًا؛ الأداة لا تستخرجها من Markdown تلقائيًا.

استخدم مخطط المثال التالي بوصفه **بيانات تعليمية**، وصدّر معرّفات المشروع الفعلية دون تغييرها. الحقول الزائدة مسموحة لحفظ مواضع المصدر. الحقول المرجعية قوائم IDs؛ مصدر الطلب قد يكون قسم محادثة معروفًا لا URL مصطنعًا.

~~~json
{
  "schema_version": 1,
  "scope_note": "مثال تعليمي صغير فقط؛ ليس سجل مشروع",
  "scope_complete": true,
  "sources": [
    {"id": "SRC-1", "location": "نص الحالة التعليمية: طلب إظهار المرجع"}
  ],
  "requirements": [
    {"id": "FR-1", "text": "عرض مرجع الطلب بعد نجاح الإرسال",
     "source_ids": ["SRC-1"], "approval_status": "draft"}
  ],
  "acceptance": [
    {"id": "FR-1/AC-1", "text": "إرسال ناجح يعرض المرجع المرتبط بالطلب",
     "requirement_ids": ["FR-1"]}
  ],
  "backlog": [
    {"id": "US-1", "title": "إرسال طلب واستلام مرجعه", "type": "Story",
     "requirement_ids": ["FR-1"], "acceptance_ids": ["FR-1/AC-1"],
     "blocked_by": [], "readiness": "ready", "unresolved_blockers": []}
  ],
  "external_dependencies": []
}
~~~

- approval_status: draft / in_review / approved / withdrawn؛ approved يحتاج approval_evidence نصًا ذا مرجع. وجوده لا يثبت صحة الاعتماد.
- readiness: draft / needs_refinement / ready / blocked؛ ready يحتاج قبولًا معروفًا، أو completion للاستكشاف/التمكين، ولا يحمل unresolved_blockers.
- type: Story / Bug / Enabler / Spike؛ يمكن حفظ تصنيف المصدر الأصلي بحقل إضافي، ولا تغير تصنيف الفريق ليطابق الأداة.
- العنصر الذي لا يرتبط بمتطلب يحتاج rationale يشرح الهدف، لا متطلبًا وهميًا لتمرير الفحص.
- blocked_by يشير إلى عنصر داخل السجل أو اعتماد خارج النطاق معرف في external_dependencies مع reason ومصدر/مالك حين يتوفران. لا تنشئ اعتمادًا خارجيًا صوريًا لإخفاء رابط مفقود.
- scope_complete إعلان من مُعد الفهرس عن النطاق المذكور فقط، ولا تستطيع الأداة إثباته. سجل الاستبعاد والنسخة ومقارنة عدد العناصر مع المصدر. الصفر ليس نجاح تغطية.
- تفحص الأداة الهوية والحقول والإحالات والحجب الذاتي والدورات وأيتام الروابط؛ تتعامل مع السحب الموثق منفصلًا عند عد المتطلبات النشطة. لا تغير حالات الطلب أو الاعتماد لتصفير التحذيرات.

تفسير الإخراج: الأخطاء خلل في الفهرس أو تناقض بنيوي يحتاج مراجعة؛ التحذيرات قد تكون نقصًا حقيقيًا أو تفصيلًا لم يحن وقته. الأعداد تغطية روابط معلنة فقط، وليست تغطية سلوكية أو اختبارات منفذة. راجع معنى النص والمصدر والقرار بنفسك.

## مقارنة سجلين قبل التغيير وبعده

شغّل: python3 scripts/check_analysis.py AFTER.json --baseline BEFORE.json. أبقِ --strict اختياريًا. يراجع الفاحص بنية السجلين أولًا؛ لا يجري مقارنة إذا وجدت أخطاء بنيوية. أضف scope_key ثابتًا غير فارغ للنطاق نفسه في النسختين، مثل "report-export"؛ ليس رقم إصدار. ضع رقم الإصدار/تاريخ التصدير في حقل جذر إضافي، لا تغير scope_key لكل نسخة.

إذا اختلف scope_key الصريح يتوقف جزء المقارنة ويصدر تحذيرًا؛ إذا غاب عن أحد الطرفين تصدر ملاحظة تطلب التحقق من قابلية المقارنة. scope_complete الجزئي يبقى معلنًا. تطابق المفتاح إعلان نطاق، وليس إثباتًا أن كل وثائق المشروع صُدرت.

تعرض change_review المعرّفات المضافة، والغائبة عن الفهرس الحالي، والحقول المختلفة لكل مجموعة. يتجاهل اختلاف ترتيب قوائم الإحالات، ويحفظ ترتيب القوائم الأخرى. يقارن قيم الحقول ولا يفسر معناها؛ اختلاف الصياغة قد يكون تحريريًا أو سلوكيًا. لا يستنتج إعادة تسمية أو تقسيمًا تلقائيًا من تشابه النص.

يتتبع أثر تغير مصدر إلى متطلب، ومتطلب إلى قبول/عنصر عمل، وقبول إلى عنصر عمل وفق الإحالات المعلنة. يحذر إذا بقي سجل مرتبط دون تغيير، أو تغير متطلب مع بقاء دليل اعتماده نفسه. هذه طلبات مراجعة وليست أوامر تعديل؛ قد يثبت المحلل أن القبول الحالي ما زال كافيًا أو أن التفويض يشمل التعديل. لا تخترع تغييرًا أو اعتمادًا لتصفير التحذير. الاعتماديات الأخرى وأثر التغيير الدلالي عبر الوثائق تحتاج مراجعة بشرية؛ الأداة لا تحسب كامل أثر المشروع.

افسر absent_from_current_index بأنه غياب من النسخة المصدرة فقط. اربط الغائب بخريطة المصير والمصدر: سحب/دمج/نقص تصدير/خارج العينة. راجع النفي والاستثناء والأدوار والزمن ولو لم يُصدر الفاحص تحذيرًا. لا تَعُد «كل الحقول مختلفة» دليل مراجعة كافية أو جاهزية معتمدة.

## الإنهاء بعد المراجعة

أصلح ما شمله التكليف ثم أعد الفحص الذي يتأثر بالإصلاح. لا تكرر كامل الفحوص بلا سبب. سلّم الجاهز للقرار المقصود وحدود التحقق والمسائل المؤثرة وأصحابها. عند تعذر بيئة أو اتصال، أكمل التحليل المستقل وحدد ما لم يُثبت عمليًا.
